# 02 · 输出系统：把漏洞变成身份资产

> 你现在的产出链是：洞 → 报告 → 平台结算 → 结束。
> 本篇加一环：洞 → 报告 → **脱敏公开输出** → 复利。
> 复利的三个形态：技术复利（写清楚才算真懂）、身份复利（被人认识）、机会复利（活来找你）。

---

## 一、为什么「交了报告就结束」是浪费

一个洞你已经付出了全部成本：找、验、写、提交。**再多花 40 分钟做脱敏输出，边际成本极低，但产出的是另一种资产**：

| 只交报告 | 交报告 + 输出 |
|---|---|
| 收入 = 赏金 × 1 | 收入 + 技术复利（写不出「为什么」= 没真懂） |
| 知识留在 vault（只有你能查） | 知识变成公开名片（别人能搜到你） |
| 下次同类洞还得自己想一遍 | 下次同类洞你自己会搜到自己的文章 |
| 简历上写「提交过 N 个漏洞」 | 简历上写「有 N 篇公开技术分析 + 链接」 |

> **和 04_闻一知十 的关系**：那篇讲「一个洞泛化成一个家族」是**横向**复利（同类目标变多）；本篇讲「一个洞变成一篇输出」是**纵向**复利（单次发现的价值层数变多）。两条一起做，一个洞能吃四次。

---

## 二、四级输出阶梯（按门槛从低到高，从第 1 级开始，别跳级）

### 级 1 · 家族检测脚本（门槛最低，收益最直接）

把重复三次以上的验证写成一个检测脚本，公开到 GitHub。

- **为什么先做这个**：你已经会写 Python，零新技能；`cnvd-lab/tools/` 里那些脚本稍加脱敏就能发。
- **公开的价值**：这类工具在中文安全圈**极易被 star/转发**（大家都在找国产组件的检测手段），是你最快攒下 GitHub 存在感的路径。
- **纪律**：只做**检测**（判断存在性），不做**利用**（拿权限/拿数据）。这条线既是合规线，也是你能公开传播的安全垫。

```
输出物：<家族名>-scanner
  ├── README：家族原理（3 段）+ 用法 + 误报说明 + 修复建议
  ├── scan.py：检测逻辑，默认只读、支持 --dry-run
  └── CHANGELOG：每次新发现的成员组件都记一行（这就是你的家族地图公开版）
```

### 级 2 · 脱敏技术笔记（每个洞 40 分钟）

**脱敏规则（硬要求，写死）**：

| 必须去掉 | 换成 |
|---|---|
| 目标域名/IP/公司名 | 「某能源行业平台」「某高校业务系统」 |
| 真实凭据/token/密钥 | `<REDACTED>` |
| 真实用户数据（任何一条） | 你自己造的样本数据 |
| 可定位到具体系统的截图 | 打码到只剩技术相关部分，或本地重绘 |
| 未修复的 0day/1day 细节 | 等官方修复+公告后再发（**这条是行业规矩，也是保命规矩**） |

**结构固定五段**（就是 04 篇的案例卡格式，直接复用）：

```markdown
# <家族名>：<一句话现象>
## 模式（抽掉名词的结构）
## 神谕（当初是什么信号让我确认的）
## 检测（脚本/指纹在哪，怎么复现验证）
## 修复（给开发者的建议——这段决定你的专业形象）
```

> **修复段是身份资产的核心**：只写「怎么打」的人是脚本小子，写清「为什么这样修才够」的人是安全研究员。你那份 JimuReport 报告的修复建议精确到路径——**把这个习惯搬到公开输出里，它就是你和其他人最大的区别。**

### 级 3 · 家族综述（攒够 3 个同类实例后写）

同一家族的三个实例 → 一篇「XX 类问题的系统性分析」。这是**你独有优势能发挥的地方**：

- 你有雷达表（同构目标集）→ 别人写不出「这类问题在国产低代码生态里的分布」
- 你有补丁 diff 流水线 → 别人写不出「官方三次修复的演进说明了什么」
- 这类文章的传播力和生命力都远超单点 writeup（会被引用、被当教材）

### 级 4 · 工具/方法论开源（半年后考虑）

当某个家族检测脚本长出「多目标批量 + 结果去重 + 报告生成」的能力，它就是一个真正的开源工具了。此时你已经有：使用者、issue、star 历史——**这是求职/接单/进安全团队时最硬的证据**，比任何证书都硬。

## 三、输出渠道（按投入产出排序）

| 渠道 | 投入 | 回报 | 建议 |
|---|---|---|---|
| **GitHub** | 低（脚本+README） | 长期复利最强，可被搜索/引用 | **主渠道**，级 1 和级 4 都放这 |
| 个人博客（GitHub Pages 免费） | 中 | 级 2/3 文章的家，自己的域名=自己的地盘 | 第 2 个月起，静态站即可，别折腾样式 |
| 先知社区 / FreeBuf / SeeBug 论文 | 中（有审稿） | 中文安全圈能见度，有稿费 | 级 3 综述投这里，命中率不错 |
| 平台排行榜（补天/漏洞盒子） | 已在做 | 圈内可见的身份证明 | 顺带的，不用特意经营 |
| 公众号/知乎 | 高（运营成本） | 破圈但杂音多 | **不建议现在做**，等级 3 有存货再说 |
| Twitter/X · 英文圈 | 高（语言+文化成本） | 天花板最高 | 第二年考虑，从翻译自己的级 3 文章开始 |

**起步节奏（不要一次全开）**：

```
第 1 月：GitHub 建仓库 + 发 1 个家族检测脚本（级 1）
第 2 月：GitHub Pages 起博客 + 2 篇脱敏笔记（级 2）
第 3-6 月：每月 1-2 篇级 2，攒够 3 个同类实例
第 6 月+：写第一篇级 3 综述，投先知
```

## 四、把 AI 装进输出流水线

输出最大的敌人是「今天太累了不想写」。用 `04_AI私教` 的角色把成本压到 40 分钟：

```
1. 素材（5min）：把当天的假设日志 + 案例卡（已脱敏）丢给 AI
2. 起草（10min）：「按 dojo 级 2 的五段结构写一篇技术笔记，受众是
   有基础的中文安全从业者；修复建议段要具体到代码/配置层面」
3. 审稿（10min）：换一轮对话让 AI 挑刺——
   「你是甲方安全负责人，这篇文章的修复建议你服不服？哪段像空话？」
4. 人工定稿（15min）：你只改技术准确性和语气，不从零写
```

> **纪律**：AI 起草可以，**技术判断必须你来**。发出去之前问自己一句「这里面每一行我都能当面讲清楚吗」——讲不清楚的句子删掉。署名是你的，责任也是你的。

## 五、合规与安全（这一节不是套话，是你的职业寿命）

| 风险 | 防线 |
|---|---|
| 泄露未修复漏洞 | **修复+官方公告之后再发**；拿不准就问平台/委托方；CNVD 通用型提交后有披露节奏，跟着它走 |
| 泄露委托方信息 | 授权协议里通常有保密条款——**签约时就把「能否公开脱敏技术分析」问清楚**，拿到书面许可再写。拿不到就不写这个目标，写你自己搭的本地环境的同类复现 |
| 输出被当武器 | 级 1 只做检测不做利用；不给可直接打真实目标的完整 exploit；不写「一键 getshell」 |
| 侵犯上游版权 | 你的 vendor 目录已经示范了正确做法：核验许可证 + 署名 + 附许可证全文。引用别人文章给链接，不整段搬 |
| 真实数据入文 | 脱敏规则表贴在手边；发布前用「如果目标公司看到这篇文章会怎样」自检一遍 |

> **一句话**：**输出要让你更专业，不是让你更暴露。** 你的红线体系（不脱库/不破坏业务/不保留信息）在公开输出上同样成立，只是对象从「委托方」变成了「不特定的读者」。

## 【学习建议】

1. **本周就做级 1**：从 `cnvd-lab/tools/` 挑一个你最熟的脚本（`unauth_enum.sh` 就是好选择），脱敏 + 写 README + 建新仓库发出去。这一步的心理门槛远大于技术门槛，做完了后面都顺。
2. 别追求文章质量完美。**前 5 篇的目标是「发出」，不是「精彩」**——写作能力靠篇数长出来，跟触发器表靠行数长出来是同一个道理。
3. 输出节奏挂在你的减量周上：每月第 4 周（03 篇的减量周）本来任务轻，正好用来写级 2/级 3。**不要让输出抢实战时间**，它是实战的副产品，不是第二份工作。
4. 公开输出会给你带来第一次「被人问问题」——**认真答**。这是你从「独立学习者」变成「有同行的人」的入口，也是独立学习最缺的那味药（同伴反馈）。
