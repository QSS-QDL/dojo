# 03 · 训练回路：让智库当陪练，让知识过手

> 前置：`02_心智模型` 六篇（训练的是那六个框架）+ `01_智库评估` 的三铁律。
> 本篇解决「读了很多，手不会」——把六模型转成可重复的训练菜单。

---

## 一、训练回路的四要件

一次有效训练必须同时具备四样，缺一样就退化成「读书」：

| 要件 | 说明 | 缺失的后果 |
|---|---|---|
| **靶** | 一个具体、可动手的对象（本地部署的真实系统 / 授权资产） | 无处落地，读完就忘 |
| **限** | 时间盒（20/40/90 分钟），到点必停 | 无限期漫游，进度幻觉 |
| **判** | 明确的对错信号（神谕 / 验收清单 / AI 批改） | 练错了也不知道，形成坏习惯 |
| **沉** | 产出物（假设日志 / 案例卡 / 一行触发器） | 复利归零，每次从零开始 |

> **你的现状对照**：27 天计划有靶（雷达表）+ 限（三块制）+ 判（当日验收）+ 沉（狩猎卡）。**结构已经对了。** 本篇不是替换它，是给它一套「技术动作训练」补充——像运动员除了打比赛还要做体能分解动作。

## 二、让 grimoire 当陪练：四种查询姿势

智库的价值不在「读」，在「被正确地打断」。四种姿势：

### 姿势 A：症状查询（作战中）
遇到报错/异常响应 → 把**原文**贴进症状搜索。这是 grimoire 最强的机制（WRAITH 同款）。
**纪律**：查到技法后，先自己写一行「我预期这个 payload 在这里生效的原因」，再动手。**猜对了才算学到，猜对了还打中了才算会。**

### 姿势 B：反向查询（训练后）
打完一个 drill，用你**实际用到的技术名**查库，看有没有更好的做法/你没想到的变体。
**纪律**：只读**前三条**结果，各写一行「与我的做法差异在哪」。读完就退，不漫游。

### 姿势 C：缺口查询（每周复盘）
拿 `02_边界地图` §三 的十二条边界表，每周挑一条你**最薄**的，查库看有什么，**然后立刻判断「库里够不够」**——不够就去外部补（见 `05_基础补全`）。
这是把「智库盲区」变成「本周学习项」的机制。

### 姿势 D：抽卡复习（碎片时间）
`kb_random` 随机一篇 → 30 秒内说出：**它属于哪条边界？源头/汇点是什么？我的触发器表里有它吗？** 说不出 = 记进缺口清单。
> 学习抽卡你已经在 README 里做了按钮，但没定规则。**规则就是上面这三问。**

## 三、训练菜单（六个 drill，每个都带四要件）

> 用法：**每天挑 1 个 drill 放进晚间块**（30-60 分钟），不要贪多。
> 所有 drill 的靶都是「本地部署的真实系统」或「授权资产」，不刷 CTF 题（尊重你 R01 的立场）。

### Drill 1 · Canary 地图（30 分钟）｜练 01 数据流

- **靶**：本地部署的一个雷达表系统（若依/JeecgBoot 类）
- **动作**：向 5 个源头（URL 参数 / body / Cookie / User-Agent / 上传文件名）各送一个唯一 canary（`CANARY_A1`…），用浏览器+代理+日志+数据库搜出每个 canary 落在哪
- **判**：能画出一张「源头 → 落点」表，至少发现 1 个「意外落点」（进了日志/进了别的页面/进了 SQL 报错）
- **沉**：vault 新建 `数据流-<系统名>.md`，四段式（源头/路径/汇点/净化级别）
- **智库姿势**：B（打完查 `log injection`、`second order` 看你漏了什么）

### Drill 2 · 边界速写（20 分钟，纯被动）｜练 02+05

- **靶**：一个**没碰过**的目标（授权范围内）或本地系统
- **动作**：只用 `curl -v` 首页 + 3 个只读请求，画出十二条边界图，标出「确认存在/猜测/未知」，写出前 3 优先攻击面
- **判**：AI 批改——把你的图喂给 AI（`04_AI私教` 的「陪练官」模板），让它指出你漏了哪条边界、哪个推断证据不足
- **沉**：vault `边界图/<产品名>.md` + 目标卡更新
- **智库姿势**：D（抽卡时问「这个属于我图上哪条边界」）

### Drill 3 · 触发器实战（40 分钟）｜练 03

- **靶**：授权资产（【实】块顺带做）或本地系统
- **动作**：全程用假设日志格式记录，**至少 8 行**，每行必须先写预测再看结果
- **判**：命中率 + 至少 2 次「假设被否但记下了为什么」
- **沉**：假设日志入库 + 触发器表新增 ≥1 行（新现象→新假设）
- **智库姿势**：A（症状查询，每次查询前写下你的预期）

### Drill 4 · 补丁考古（60 分钟）｜练 04

- **靶**：一个你雷达表里组件的**历史**安全补丁（GitHub commit / release note）
- **动作**：拉修复前后两版，diff 出安全相关变化，反推「原来怎么被打」，写受影响版本区间
- **判**：能一句话说清「修了什么根因」（对应 01 篇的「净化哪一级失效」）
- **沉**：vault 案例卡（五段式）+ 雷达表标记受影响版本
- **智库姿势**：先搜 CVE 编号看库里有没有分析，有就对照你的结论

### Drill 5 · 一次防御方（60 分钟，每两周一次）｜练 06

- **靶**：本地 nginx + Coraza/ModSecurity + 你自己的十行 Flask 漏洞应用
- **动作**：自己拦自己。记录命中的规则 ID 和正则 → 针对每条推一个绕过 → 验证
- **判**：对照表 ≥5 行，每行标注「差异类 or 盲区类」
- **沉**：vault `MOC-现代防护对抗` 追加对照表
- **智库姿势**：B（查 `WAF bypass` 看有没有你没想到的机制）

### Drill 6 · 家族扫描（40 分钟）｜练 04+02

- **靶**：本地部署一个宿主系统
- **动作**：读它的依赖清单（`pom.xml`/`package.json`/lib 目录）→ 列出所有内嵌组件 → 逐个访问其默认路径 → 记录哪些「宿主没给它套闸」
- **判**：产出该宿主的完整寄生组件清单，至少 1 个「无闸」发现
- **沉**：更新 `unauth_enum.sh` 的路径字典 + 家族案例卡
- **智库姿势**：A（组件名 + `unauthorized`/`default password`）

## 四、周节奏：怎么把 drill 塞进你现有的三块制

**不改 27 天计划**，只做两处插入：

| 时段 | 原计划 | 插入 |
|---|---|---|
| 晚间块前 40 分钟 | 学习/复盘 | **1 个 drill**（按当日主线选：Java 日→Drill 4，实战日→Drill 3，测绘日→Drill 2/6） |
| 周复盘（已有的《周复盘模板》） | 复盘 | 加三行：本周 drill 完成数 / 触发器表新增行数 / 命中率趋势 |

**四周一个循环的强度设计**：

```
W1  Drill 1+2+3（打基础：看清数据流和边界）
W2  Drill 3+4+6（出成果：实战假设 + 补丁 + 家族）
W3  Drill 2+4+5（补防御视角）
W4  减量周：只做 Drill 3，其余时间用于「补智库缺口」（01_智库评估 §一.4 的三个薄区）
```

> **减量周不是偷懒**，是刻意练习的必要部分。没有减量周的四周计划，第四周必然崩——这是你 27 天计划「可持续优先于进度」的月度版。

## 五、训练日志：一页纸的自我量化

在 vault 建 `训练日志.md`，每周一行，**只填数字**（数字才能看出趋势，文字会自欺）：

| 周 | drill 数 | 假设命中率 | 触发器表行数 | 案例卡数 | 智库缺口补了几条 | 一句话 |
|---|---|---|---|---|---|---|
| W1 | | | | | | |

**四个指标的健康区间**（低于下限说明训练变形）：

- drill 数：3-4/周（>5 = 贪多，每个都没做透）
- 命中率：从 25% 爬向 50%（一直 70%+ = 你在挑软柿子，假设不够大胆）
- 触发器表行数：+2~5/周（不涨 = 你在重复已知的东西）
- 案例卡数：+1/两周（不涨 = 有发现但没资产化，最可惜的浪费）

## 【学习建议】

1. **从 Drill 1 和 Drill 3 开始**，这两个直接对接你今天的实战，反馈最快。其余四个按周节奏表轮。
2. drill 的价值在**做透一个**，不在做完六个。第一次做 Drill 1 大概会超时到 60 分钟——正常，超时说明你在学新动作；第三次还超时说明靶选得太复杂，换个小系统。
3. **每个 drill 的「沉」不可跳过**。你的病灶是 94% 搬运型笔记，而「沉」环节强制写的都是判断层（预期/差异/根因）。跳过沉淀 = 白练。
4. AI 是这里最便宜的裁判：Drill 2 的边界图、Drill 3 的假设日志、Drill 4 的根因一句话，都可以直接丢给 AI 批改——用法见 `04_AI私教/01`。
5. 冲刺期（→10/13）只做 Drill 3（顺带在【实】块里，零额外时间）。10/14 之后开始完整周节奏。
