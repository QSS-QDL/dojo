# 10 · 国产组件家族手册：指纹 → 默认面 → 历史漏洞面 → CNVD 泛化点

> **你的雷达表主粮册。** 国产企业系统 = 宿主 + 内嵌组件的寄生结构（dojo 02_心智模型/02 §四），
> 本篇按家族给「判定五件套」。历史漏洞面全部是**已公开已修复**的识别级信息（细节与 PoC 查 CNVD 库/grimoire），
> 用途：版本判定 → 对号入座 → 按 04 篇补丁 diff 流水线做通用型论证。
> 与雷达表的关系：本篇每个条目 = 雷达表的一类行；`unauth_enum.sh` 的字典源。

## 〇、通用工作流（每个组件都这么打）

```
① 指纹判定（本篇各条的「指纹」段，被动优先）
② 版本定位（静态资源哈希/报错/功能特征/官方更新日志比对）
③ 默认面检查（弱口令/未授权路径——一次尝试级，01 篇 §3 纪律）
④ 历史漏洞面对号（版本落在哪个已知区间 → CNVD/NVD 查编号 → 本地部署同版本验证）
⑤ 泛化（dojo 04 篇四问）：同组件其他宿主 / 同宿主其他组件 / 版本区间 → 雷达表回填
⑥ 产出：案例卡（五段式）+ 检测规则进 unauth_enum + 报告（07_SRC/05 标准）
```

## 一、若依 RuoYi 系（衍生系统最多的国产脚手架）

| 项 | 内容 |
|---|---|
| **指纹** | 登录页「RuoYi」字样/若依默认样式；静态资源 `/ruoyi/`（或改名后的同款结构）；`rememberMe` cookie（Shiro 版）；Vue 版前端 chunk 命名；页脚「© 2018-20xx 若依」 |
| **变体** | RuoYi（单体）/ RuoYi-Vue（前后端分离）/ RuoYi-Cloud（微服务）/ RuoYi-App / 海量改名衍生（**结构不变皮变**——指纹看结构不看名字） |
| **默认面** | admin/admin123（一次尝试）；Druid monitor `/druid/`（内嵌，见 §六）；Swagger `/swagger-ui.html`（开发态未关）；`/profile` 上传目录 |
| **历史漏洞面（识别级）** | Shiro 默认 key 反序列化（部分版本硬编码 key 在公开清单）；数据监控 order by 参数 SQL 注入（`${}` 结构位，01 篇 §四的典型产地）；`/common/download/resource` 路径穿越（resource 参数）；定时任务功能 RCE（**需管理员权限**——所以常与弱口令/越权链式组合）；GenTable 相关注入面 |
| **CNVD 泛化点** | 衍生系统数百个：指纹按「结构特征」抽（登录 API 路径 `/login`+`/captchaImage` 组合、`/system/user` 接口命名习惯），一个版本区间洞=一批衍生站候选；雷达表按「若依衍生」生态列行 |

## 二、JeecgBoot + JimuReport（低代码双子星，你的成名生态）

| 项 | 内容 |
|---|---|
| **指纹** | JeecgBoot：`/jeecg-boot/` 上下文、登录页 Jeecg 样式、`/sys/login` 接口；JimuReport：`/jmreport/list`（**未授权面的正主**）、`/jmreport/show/`、报表设计器页面特征 |
| **默认面** | JeecgBoot 默认 jeecg/123456（一次尝试）；`/jmreport/list` 无鉴权可达（你的战例）；Druid/Swagger 内嵌；`/sys/common/static` 静态资源面 |
| **历史漏洞面（识别级）** | JimuReport：queryFieldBySql 类接口 SQL 注入（多个编号）；FreeMarker SSTI（06 篇 §一 的主战场——数据集预览功能）；show 页面未授权信息泄露；版本间反复修的鉴权补丁（**补丁 diff 流水线的最佳教材**——它修得勤，diff 素材多）；JeecgBoot 主体：用户列表接口未授权（历史版本）、AutoPoi 导入导出面、`/testOrder` 类示例接口未删 |
| **CNVD 泛化点** | JimuReport 被大量第三方系统集成（宿主千姿百态，组件指纹统一=`/jmreport` 路径族）——**组件级指纹比宿主级指纹泛化效率高一个量级**；每个新 CVE 出来先跑全网 `/jmreport` 测绘（授权范围内），版本区间论证直接引用官方更新公告 |

> OA 类通用泛化点：三家都有海量「改名贴牌」衍生（XX 办公系统=通达换皮）——指纹看 `/general/index.php` 类**路径结构**而非标题文字；OA 的洞常是「上传×包含×鉴权」三件套组合，单点修复不彻底是常态（复测价值高）。

## 五、微服务组件：Nacos / XXL-JOB / Sentinel / Dubbo Admin

| 组件 | 指纹 | 默认/历史面（识别级） | 备注 |
|---|---|---|---|
| **Nacos** | 8848 端口；`/nacos/` 控制台（默认 nacos/nacos）；`/nacos/v1/` API 族 | 历史未授权 API（`/v1/auth/users` 增删改查面，CVE-2021-29441 的 `User-Agent: Nacos-Server` 绕过是**身份头信任**的经典教材）；Derby 内置库 SQL 面（CVE-2021-29442）；配置中心里的**数据库凭据/AK**（读到=横向钥匙，**识别即停**，02 篇 Redis 级纪律） | 云原生目标第一查；控制台暴露=配置全览 |
| **XXL-JOB** | `/xxl-job-admin` 控制台（默认 admin/123456）；执行器 9999 端口 | admin 弱口令→任务管理→执行器调度 RCE 链（**证明到登录成功即停**）；执行器 API 未授权（accessToken 默认值/为空时，历史编号多个）；调度日志泄露 | 「控制台弱口令+执行器未授权」双门结构，寄生组件教科书 |
| **Sentinel Dashboard** | 8080/8719 端口；`/` 控制台（默认 sentinel/sentinel） | 控制台未授权→规则 manipulation；历史 RCE 面（特定版本） | 与 Nacos 常同机部署（微服务全家桶） |
| **Dubbo Admin / Zookeeper** | 38080（admin）/2181（ZK） | ZK 未授权（4lw 命令 `envi`/`dump` 只读证明）；Dubbo 反序列化面（07 篇 §二 协议入口） | ZK 是微服务配置的又一把钥匙 |

> 微服务家族泛化点：**全家桶共现规律**（有 Nacos 大概率有 Sentinel/Gateway/XXL-JOB）——发现一个就把全家桶路径都探一遍（每个一发，只读）；云原生部署（K8s）时这些组件常通过 Ingress 意外暴露（配置失误面，grimoire K8s-Goat 170 篇的主场）。

## 八、家族检测的工程化（把本篇变成产线）

```
1. 指纹库结构化: 本篇每条目 → unauth_enum.sh / 自建指纹工具的一条规则
   规则四元组: {路径探针, 响应特征(状态码+body关键字+头), 组件名, 版本判定法}
2. 测绘联动: 指纹关键字 → FOFA/Hunter 语法(你 vault《方法论》的语法表) → 授权范围内圈定候选
3. 版本情报维护: 每家族的「官方更新公告页」进书签，月度巡检(新补丁=新 diff 素材=新通用型机会)
4. 案例卡回写: 每打掉一个家族实例 → 案例卡(五段式) → 家族条目的「历史漏洞面」段更新
   —— 本篇文档本身应该随你的实战每季度长厚一次(它是活文档)
```

## 【本篇学习建议】

1. **从 §一二 开始**（若依/Jeecg——你已有战例和手感），§四 OA 选通达（资料最全）做第一个「纯对号入座」练习，§五 Nacos 配 K8s-Goat 本地环境。§七 信创区放到 12 周课表 W8 之后（需要 Java 审计能力打底）。
2. 每个家族学完的固定产出：unauth_enum 加一条规则 + 雷达表加一类行 + 版本特征卡一张——**三件套齐了才算学完**（不然又是搬运）。
3. 历史漏洞面的正确用法是**识别与对号**，不是抄 PoC 打现网：版本落在区间 → 本地部署同版本验证 → 走 CNVD 流程。直接拿公开 PoC 打未验证版本，误伤率和法律风险都高（且经常打空——补丁状态未知）。
4. 本手册的空白处就是你的机会：你实战中新遇到的组件（比如某省政务云自研网关），按同样五件套格式补进来——**半年后这本手册就是全网独一份的私人情报资产**。
