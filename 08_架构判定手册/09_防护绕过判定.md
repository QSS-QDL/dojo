# 09 · 防护绕过判定：认闸 · 定位 · 分类应对 · 蜜罐识别

> dojo 02_心智模型/06 给了统一理论（差异类/盲区类/信道战争），本篇是**现场操作卷**：
> 认厂商 → 定位拦截层 → 按机制分类试探 → 识别 RASP/风控/蜜罐 → 知道何时停。
> 纪律不变：单请求、低频、可解释；L3/L4 深水区不硬抗（时间盒 40 分钟）。

## 一、认闸：防护产品指纹表

| 指纹 | 判定 | 备注 |
|---|---|---|
| `acw_tc` / `acw_sc__v2` / `acw_sc__v3` cookie；拦截页含「您的请求已被拦截」+ 阿里云样式 | **阿里云 WAF/云盾** | 国内云站最高频；acw_sc 是 JS 挑战 cookie（无头浏览器面） |
| 拦截页含 `waf.tencent-cloud.com` / `腾讯云 Web 应用防火墙` | 腾讯云 WAF | |
| `X-Sucuri-ID` / `X-Sucuri-Cache` / 拦截页 `sucuri.net` | Sucuri | 海外站常见 |
| `cf-mitigated: challenge` 头 / `__cf_bm` cookie / 挑战页含 `Cloudflare` | Cloudflare | 免费档位规则相对可预期；企业档难 |
| `Server: awselb/2.0` + 403 XML `RequestId` | AWS WAF/ALB | |
| `jsl_clearance` / `__jsluid` cookie | 加速乐/知道创宇 | JS 挑战类 |
| 拦截页「网站防火墙」「SafeDog」 | 安全狗 | 老牌主机+云 WAF |
| `Yunsuo` / 拦截页云锁样式 | 云锁 | |
| 拦截页含「长亭」「雷池」`X-Safeline-*` 头 | 长亭雷池 | 国产新锐，语义分析型（L2 级） |
| 深信服 AF 拦截页 | 深信服 | 常与内网 AF 设备联动 |
| 403 + `ModSecurity Action` / 事件 ID 格式 | ModSecurity/CRS（开源） | **好事**：CRS 规则公开可查（06 篇防御者视角的本地陪练就是它） |
| 拦截页含事件 ID+二维码/工单号 | 国产云 WAF 通用形态 | 事件 ID 可写进报告（帮厂商对账） |

**无指纹的拦截**（403 但没有任何厂商标识）：自研网关/中间件级 ACL/应用自身校验——**拦截层定位（§二）比认厂商更重要**。

## 二、定位拦截层：五步法（10 个请求内画出防御画像）

```
第1发  无害 canary（纯字母数字参数）           → 200 = 基线
第2发  canary + 单引号                        → 被拦 = 字符级规则（L1 静态）
第3发  canary + 完整良性 SQL 片段(SELECT 1)    → 被拦而第2发没拦 = 关键字级
第4发  第3发的变形(大小写/注释切割)            → 过 = L1 黑名单确认；仍拦 = 疑 L2 语义分析
第5发  无害请求高频 ×10（对自己的测试账号）     → 触发验证码/429 = L4 风控存在及阈值
读拦截响应三要素:
  状态码(403/405/406/999 类自定义码) · body(厂商页/框架页/业务 JSON) · 头(有没有新增 Set-Cookie/事件ID)
  三要素组合 = 拦截者身份（应用/WAF/中间件，05 篇报文即证据 §2.3 的展开）
后端确认(有权限时): 目标应用日志里有没有这条请求 → 没有=WAF 前置拦截；有=应用层拒绝
```

**画像产出**（写进目标卡）：`厂商=? 级别=L? 拦字符还是拦语义 风控阈值≈? 拦截是否可观测(事件ID)`——这张画像决定后面每个漏洞类的探针设计（比如 L2 语义型就别浪费时间做字符变形，直接找业务合法输入切入）。

## 三、绕过机制四分类：按「闸的原理」选钥匙

> 实例 payload 全在 grimoire PATT（223 篇）/HackTricks，此处只给**选择逻辑**和每类的「可用性判定探针」。

### 类 1 · 编码差异（闸解码次数/方式 ≠ 后端）
```
可用性判定: 目标是否多层代理(有 CDN+nginx+应用 → 解码点越多机会越大)；
            拦截是否基于「解码后文本匹配」(第4发变形被拦说明它做了解码归一)
弹药方向: URL 编码层数(单/双/混合) · Unicode 变体(全角/上标/组合字符) · 
          HTML 实体 · charset 声明差异(Content-Type 带 charset=ibm037 类冷门编码——历史有效面)
判定探针: 同一个被拦 payload 的 3 种编码变体各一发，哪种过了记哪种
```

### 类 2 · 等价替换（闸的关键字表不全）
```
可用性判定: L1 静态黑名单（第2/3发拦、第4发部分变形过）
弹药方向: SQL 函数等价链(substring/mid/substr/left+right · ascii/hex/ord · sleep/benchmark/get_lock/大查询)
          注释切割(UNI/**/ON · /*!50000UNION*/) · 大小写 · 冷门语法(科学计数 1e0 · 十六进制 0x)
          XSS 侧: 冷门标签/事件(06 篇 §二) · JS 编码(\x61\u0061 · String.fromCharCode · 模板字符串拼接)
判定探针: 一个语义 3 种写法，逐个试到命中（每发间隔 ≥ 正常人工节奏）
```

### 类 3 · 结构差异（闸解析的请求 ≠ 后端解析的请求）
```
可用性判定: 多层架构 + 闸在中间（CDN→WAF→nginx→应用）
弹药方向: HPP 同名参数(前后取值差异) · Content-Type 切换(form↔json↔xml↔multipart——闸按 A 解析、后端按 B)
          chunked 分块切割关键字 · HTTP/1.0 vs 1.1 vs 2 · 头顺序/重复头 · 
          multipart 的 boundary 变形与文件名编码 · 路径归一化(08 篇 §七 十变体——鉴权闸的主 bypass)
判定探针: 双份参数各带一半 payload(「拼接后才完整」)——过了=HPP 差异存在
纪律: 走私级(08 篇 §六)判定用时间差法，不注入跨用户内容
```

### 类 4 · 信道切换（闸杀了神谕，换一个）
```
dojo 02_心智模型/06 §五 信道战争全套: 时延被熔断→布尔→报错→OOB→站内二次信道
判定: 02 篇的五步画像里「第5发触发风控」+ 时延探针失效 = 需要切换
最有价值: 站内二次信道(数据落到自己可见页面/导出/邮件)——合规最优(无出网、无副作用)
```

## 四、RASP 判定（应用内防御）

```
特征组合(满足 2 条以上疑 RASP):
  ① payload 变形全无效（各种编码/等价都被拦，且拦截文案统一）
  ② 拦截发生在「执行点」: 报错含应用框架堆栈但请求被中断(而非 WAF 页)
  ③ 无害的业务请求带敏感值也拦(如搜索框搜 "select * from" 被拦但 ' 单发不拦——函数级语义监测)
  ④ WAF 日志(若可见)无记录但应用侧拦了
应对(L3 阶梯): payload 变形无意义 → 换执行通道思路(让 DB/系统自己干活: 存储过程/DB端函数/计划任务特性——
  概念级理解，实操仅限靶场) → 或换攻击面(逻辑洞/越权不经过注入执行点，RASP 管不到——
  **这就是为什么逻辑洞在重防护目标上价值更高**: 05 篇认证册 + 07_SRC/04 §3-4 是你的 RASP 时代主力)
```

## 五、速率限制与风控（L4）判定与合规策略

```
判定: 第5发画像的阈值测试(对自己账号) · 429/验证码/临时封禁的触发点 · 
     限的是 IP 还是账号还是设备指纹(换小号试)
合规策略(红线内): 
  ① 不爆破不压测——把请求预算花在「高价值假设」上(03 篇触发器表的经济学)
  ② 低频精准: 每天固定少量请求的「细水长流」测试节奏，天然低于风控阈值
  ③ 被封后: 不绕封(换 IP 绕封=对抗升级，且可能违反授权条款)——记录、等待、换面
  ④ 验证码: 手动通过自己的测试流程可以，打码平台+自动化=爆破节奏，红线
  报告价值: 风控策略本身可测出「配置缺陷」(限 IP 不限账号/阈值过宽/验证码可复用——05 篇 §七)，
           这些是合规且有价值的产出
```

## 六、蜜罐判定（打之前先问：这是真的吗）

```
蜜罐特征组合(≥3 条即高度怀疑):
  ① 服务组合不合逻辑: 一台机器同时开 21/23/445/1433/3306/6379/9200 全都有服务(真实生产不会这样)
  ② 响应过于完美: 任何路径都 200 · 任何漏洞探针都「成功」· banner 版本齐全且都是经典漏洞版本
  ③ 时间矛盾: Server 头说 2019 年的版本但 TLS 证书昨天签发 · 响应时间恒定(仿真)
  ④ 交互异常: 你发的畸形请求它返回「正常」响应(真系统会报错) · 命令执行回显内容像模板
  ⑤ 已知蜜罐产品指纹: HFish/Elk not·T-Pot·Cowrie 类默认页特征
处置: 怀疑即撤——蜜罐上的一切「成果」无效且你的行为全程被记录(可能反向关联你的真实身份/告警到你的委托方)。
     雷达表标记「疑蜜罐」+特征记录(这本身是情报)。
反直觉要点: 蜜罐多发于「看起来太肥」的目标——全端口开放的孤儿 IP、经典漏洞版本集合体。
     真实世界的肥肉(未授权 Redis 们)通常长在业务系统的边角，不是独立裸 IP。
```

## 【本篇学习建议】

1. **本篇的正确打开顺序是倒的**：先学 §六 蜜罐判定和 §二 五步画像（防错），再学 §三 四分类（进攻），§四§五 当参考。多数人反过来学，结果第一天就在蜜罐上「出成果」。
2. 四分类不是四选一，是**判定树上的四条分支**：画像(L1?)→类2；多层架构→类3；编码可变形→类1；神谕被杀→类4。先画像后选钥匙，别拿着一把钥匙找锁。
3. 本地陪练（06 篇防御者视角 §六 的延伸）：nginx+Coraza 起靶 → 把 §三 四类弹药各打一轮 → 记录哪类过了哪条规则——**你将来报告的「修复建议」段会因此值三倍**。
4. 对抗知识半衰期最短：本篇厂商表每半年自查更新一次（新产品/新指纹），机制层（四分类）十年不变——学机制、查实例，智库 PATT 就是你的活弹药库。
