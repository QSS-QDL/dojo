# 00 · 怎么用这本手册（判定树总入口）

> 你要的是「具体知识点」：怎么认出后端是什么、认出来之后怎么测、被拦了怎么绕、怎么学。
> 本目录就是这层。**它不是教材，是判定手册**——教材在 cnvd-lab `curriculum/`，百科在 grimoire，
> 这里只回答三件事：**这是什么 → 它怕什么 → 我下一步发哪个请求**。

---

## 一、核心方法论：指纹 → 假设 → 最小探针

任何一次「判断后端是什么」，都走这条链，**不要跳步**：

```
① 被动指纹（零请求，先看已有响应）
   报错文本 / 响应头 / Cookie 名 / 默认页 / 静态资源路径 / JS 里的痕迹
        ↓ 得到 1-3 个候选
② 主动指纹（1-3 个只读请求，故意触发差异）
   畸形请求看谁报错 / 默认路径是否存在 / 特定参数是否被解析
        ↓ 候选收敛到 1 个
③ 版本定位（决定用哪个 N-day、payload 怎么写）
   静态资源哈希比对 / 功能特征探测 / 报错堆栈痕迹
        ↓
④ 假设 → 最小探针验证（dojo 02_心智模型/03）
```

**三条纪律**：

1. **先被动后主动**。被动指纹零成本零风险，能解决 70% 的判定；一上来就扫目录是新手标志。
2. **判定要能说出证据**。「我觉得是 Spring」不是判定；「`JSESSIONID` + whitelabel error page + `/error` 返回 timestamp/status/path 四字段 JSON」是判定。**证据写不进目标卡的判定都是猜测**，猜测要在卡上标「猜测」。
3. **一个指纹不够就叠三个**。单指纹假阳性率高（`Server: nginx` 说明不了后端语言），三指纹交叉才下结论。

### 线索 B：没有报错（被定制/被吞）→ 用 Cookie 和响应头

| 观察 | 判定 | 备注 |
|---|---|---|
| `JSESSIONID` | Java Servlet 容器 | 再叠 `/actuator`、whitelabel 判 Spring |
| `JSESSIONID` + `route=` / `SERVERID=` | 前置 F5/负载均衡 | 多实例：盲注结果可能不一致 |
| `rememberMe=` | **Shiro** | `deleteMe` 值 = 你送的 cookie 解密失败 → 直接进 07 |
| `SESSION=<base64>` | Spring Session | `echo <b64> \| base64 -d` 看结构（只看，不改） |
| `PHPSESSID` | PHP | 找 `.php`、`/install/`、老 CMS |
| `laravel_session` + `XSRF-TOKEN` | Laravel | 查 `.env`、`APP_DEBUG`、`_ignition` |
| `csrftoken` + `sessionid` | Django | 查 `DEBUG=True`、`/admin` |
| `connect.sid` | Express/Node | 查原型污染面、JWT |
| `ASP.NET_SessionId` / `.AspNetCore.*` | .NET | 查 ViewState、`trace.axd`、`elmah.axd` |
| `acw_tc` / `acw_sc__v2` | 阿里云 WAF/盾 | 已进对抗层，见 [`08_防护绕过判定.md`](08_防护绕过判定.md) |
| `__cf_bm` / `cf_clearance` | Cloudflare | 同上 |
| `AWSALB` / `AWSALBCORS` | AWS ALB | 云上，边界⑫ |
| `Set-Cookie` 缺 `HttpOnly` | 团队安全习惯弱 | 全局降低「别处做得好」的预期 |

### 线索 C：什么线索都没有 → 主动探针（3-5 个请求）

| 探针 | 你在问什么 | 读什么 |
|---|---|---|
| `GET /` 加一个不存在的路径 `/xK9notexist` | 谁在返回 404 | 404 页长相+`Server` 头=中间件层 |
| 参数加单引号 `?id=1'` | 有没有 SQL 层、谁在报错 | 报错文本（回线索 A）/ 403（有闸）/ 无变化（参数化或未入库） |
| `POST` 同一接口，`Content-Type` 在 form/json/xml 间切换 | 后端解析器是谁 | XML 被解析=XXE 面；JSON 报错带库名=线索 A |
| `HEAD`/`OPTIONS` | 端点存在性+方法清单 | `Allow:` 头白送方法 |
| 送一个不存在的 HTTP 方法 | 谁在拒绝 | 中间件拒绝 vs 框架拒绝，文案不同 |
| 故意发畸形 HTTP（超长头/非法字符） | 哪一层的解析器先崩 | 崩的那层就是你要研究的那层 |

> **这六个探针是通用起手式**，每个都是单请求、只读、可解释（01 篇 §红线纪律）。发完基本能定栈。

## 四、每篇的固定五段结构

本目录所有分册，每个技术条目都按这五段写：

```
【判定】怎么认出它（被动指纹 + 主动探针 + 版本定位）
【语法】基础语法速查（够你读懂和构造最小验证，不是完整手册）
【测试】授权内的最小验证探针（到哪一步停 = 红线）
【绕过】防御方为什么拦得住、绕过机制归类（原理级，不是 payload 大全）
【学习】怎么练到 L2/L3（本地环境 + 智库检索词 + drill + 验收）
```

**为什么是五段而不是「payload 大全」**：payload 会过时（半衰期最短的知识，dojo 02/06 已论证），判定能力和机制理解不会。你缺的从来不是 payload（grimoire 里 PATT 223 篇 + HackTricks 1040 篇躺着），缺的是**「看到什么该想到查什么」的那一跳**——那就是【判定】段。

## 五、与红线体系的关系（本目录所有内容的边界）

1. **判定与识别**：只读、被动优先，无副作用 → 完全在授权内。
2. **最小验证**：证明「存在」即停。数据库层证明=读出 `version()`/当前库名/1 条样本；未授权证明=访问到管理页/`INFO` 返回；**不导出、不写库、不删数据、不留后门**（01 篇红线组 §14-16 全部适用）。
3. **绕过技术**：只讲**机制分类**（解析差异/规则盲区/信道切换）和判定方法，具体 payload 现场查 grimoire——不是我不能给，是**机制会了 payload 现场推导更快**，且库里比你我都全。
4. **后渗透/内存马/横向**：只到「证明可进入」，深度动作属于 HW/红队单独授权范围（01 篇 §11-14）。

> 一句话：**这本手册教你「认出来、证明到、讲清楚、修得了」，不教你「拿下来」。** 前者是你的职业，后者是你的刑期。

## 【学习建议】

1. **不要通读**。八个分册共 300+ 条目，通读=又一个搬运型笔记工程。正确用法：实战判定卡住 → 回 §二 判定树分流 → 翻对应分册那一条 → 用完把**你实际观察到的指纹**补进该条（手册会长成你自己的）。
2. **先建你的判定卡**：vault 新建 `MOC-指纹判定.md`，把 §二的三张表抄进去（线索 A/B/C），再加一列「我实测过的目标」。这张卡是你侦察速度的直接来源——dojo 02/05 篇的 30 秒建模靠的就是它。
3. **每次判定完做一个动作**：本地起一个同款（雷达表工作流），把你的指纹结论在本地验证一遍。**本地验证过的指纹才是你的指纹**，猜的不算。
4. 学新条目的固定流程（每条 30-60 分钟，别超时）：读五段 → 本地起环境 → 跑一遍【测试】探针 → 用 AI 苏格拉底模板讲一遍原理（04_AI私教 角色 1）→ 写三行进 vault（判定特征/最小探针/我踩的坑）。
