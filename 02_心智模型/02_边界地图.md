# 02 · 边界地图：攻击面是画出来的，不是扫出来的

> 心智模型 2/6 ｜ 前置：`01_数据流世界观`（数据流是纵向的河，边界是横向的闸）。
> 本篇把你的 JimuReport 战例升级成一条可复用的「漏洞家族」定理。

---

## 一、一句话内核

**每一个漏洞，都发生在某条「信任边界」上：边界一侧的数据不可信，另一侧把它当可信用了，而闸门（校验）缺失或可绕。**

数据流模型回答「污染怎么流」；边界模型回答**「地图上哪里有闸，闸该不该有」**。专家和新手的真正差距在这里：新手扫端口找洞，**专家先画边界图，再决定往哪看**——扫出来的只是「端口」，画出来的才是「攻击面」。

---

## 二、一个典型国产 Web 目标的边界清单

请求从你到数据，要穿过这些闸（按常见顺序）：

```
 你 ─①─► CDN/WAF ─②─► 网关(Nginx/F5/SpringGateway) ─③─► 应用 ─④─► 组件/中间件 ─⑤─► DB/缓存/文件 ─⑥─► 内网服务
                 │                                  │
                 └──⑦ 用户A ↔ 用户B 的数据边界        └──⑧ 低权限 ↔ 高权限（垂直越权）
                     ⑨ 数据 ↔ 指令（注入总闸）           ⑩ 宿主系统 ↔ 内嵌第三方组件（寄生边界）
                     ⑪ 人类 ↔ AI 模型（提示边界，2026 新增） ⑫ 容器 ↔ 宿主 / 云 IAM（未来线）
```

每条边界的「闸门三问」（对**每个** crossing 都问一遍）：

1. **谁在守？**（WAF？网关鉴权？应用代码？组件自己的配置？——还是没人）
2. **守的规则是什么？**（IP 白名单？token？签名？角色？所有权校验？）
3. **规则和真实执行者一致吗？**（网关解析的 URL 和后端解析的是同一个吗？组件的「内网可信」假设在公网暴露时还成立吗？）

**第 3 问产出的漏洞最多**——因为多数边界事故不是「没有闸」，是「闸和执行方对同一份数据的理解不一致」（这个不一致在 06 篇会升级成「解析差异」统一理论）。

## 三、十条边界各自的「特产漏洞」

| 边界 | 特产漏洞 | 你的现状 |
|---|---|---|
| ① 你↔WAF | 绕过、解析差异 | vault `MOC-现代防护对抗` 10 篇，有一手经验（超时熔断杀盲注） |
| ② WAF↔网关 | 请求走私（CL/TE）、路径归一化差异、`X-Original-URL` 类头越闸 | ⬜ 空白，06 篇补 |
| ③ 网关↔应用 | 鉴权前置假设失效（网关放行的路径应用没再校验）、路由解析差异 | ⬜ 薄弱 |
| ④ 应用↔中间件 | JNDI 注入、Druid/H2/Actuator/Nacos 未授权 | ✅ 你的最强项（MOC-未授权访问 8 篇） |
| ⑤ 应用↔存储 | SQLi、NoSQLi、二次注入、Redis 未授权写 crontab | ✅ SQLi 24 篇（偏 CTF，用 01 篇重构） |
| ⑥ 应用↔内网 | SSRF 打 metadata/内网组件、XXE OOB | ⚠️ SSRF 笔记少 |
| ⑦ 用户↔用户 | **IDOR/水平越权** | ❌ 智库仅 36 篇、你笔记也薄——**SRC 出单主力，最该补** |
| ⑧ 低权↔高权 | 垂直越权（普通用户调管理员接口）、前端藏菜单≠后端鉴权 | ⚠️ 有实战感，缺系统化 |
| ⑨ 数据↔指令 | 全部注入类（01 篇的河） | ✅ |
| ⑩ 宿主↔内嵌组件 | **寄生组件家族**（见 §四，你的成名战） | ✅✅ 已验证，待泛化（04 篇） |
| ⑪ 人↔AI | 提示注入、Agent 工具滥用、RAG 投毒 | 📚 智库有 src-hunter-skill LLM 篇（全库消化度最高源） |

> **学习建议**：这张表就是你的**短板账本**。每月复盘时更新「你的现状」列。别按顺序全补——**按你当前作战线补**：SRC 变现期优先 ⑦⑧（越权），CNVD 期优先 ④⑩（组件），冲刺期（现在）不动它。

## 四、把你的战例升级成定理：「寄生边界」家族

你那份 JimuReport 报告的本质，用边界语言重述：

> **宿主系统（某能源平台）在边界 ③ 做了 perimeter 鉴权，但内嵌组件 JimuReport 自带一套接口面，它在设计时假设「我只会被宿主的可信页面调用」——运行时它却直接暴露在公网用户面前。宿主的闸没有覆盖寄生者的门。**

这不是「一个 JimuReport 未授权」，这是一个**家族**，命名它：**寄生组件边界失守**。家族成员（同一结构，不同名字）：

```
报表/低代码：JimuReport、积木、UReport、AJ-Report、GoView
监控/诊断：  Druid monitor、Spring Actuator、H2 console、phpinfo、Swagger/Knife4j
任务/调度：  XXL-JOB admin、Quartz 控制台、DolphinScheduler
注册/配置：  Nacos、Eureka、Consul、Apollo
网关/代理：  Kibana、Grafana（老版本）、各种 admin 页
AI 新成员：  内嵌的 LLM 网关、向量库面板、LangFlow/Dify 类编排台（2025-26 爆发中）
```

**家族检测的本质**（你 `unauth_enum.sh` 已在做的事，现在你知道它为什么有效）：
不是「扫 URL 字典」，是**「枚举国产系统爱内嵌什么组件，然后问：宿主给它套闸了吗」**。所以这个家族的情报来源是：

1. 部署一个宿主系统（若依/JeecgBoot 衍生），看它 `pom.xml`/`package.json` 里嵌了什么 → 组件清单自动更新
2. 组件官方文档的「集成」章节 → 默认路径、默认口令、默认「是否鉴权」
3. 智库查组件名 + `unauthorized` / `未授权` → 历史案例

> **这就是「画地图」和「扫字典」的区别**：字典是死的（扫完就完），家族地图是活的（每见一个新宿主系统，地图自动长大一圈）。CNVD 通用型的复利就在这里。

## 五、画边界图的标准动作（黑盒，15 分钟，零请求或极少请求）

对任何新目标（**仅限授权范围**），先画图再动手：

```
第 1 步（5min）：被动指纹 → 猜架构
   Cookie 名/Set-Cookie 风格、Server 头、报错页长相、favicon、JS 打包名
   → 写出猜测：语言/框架/中间件/是否有 CDN/WAF（05 篇教推断细节）
第 2 步（5min）：在纸上画出请求路径图（照 §二 的模板）
   标出每一跳：哪些确认存在、哪些是猜测、哪些闸已确认在工作
   （例：302→/login 说明③有闸；/druid/index.html 直接 200 说明④的寄生门没闸）
第 3 步（5min）：产出「攻击面优先级清单」
   按「闸门可疑度 × 特产漏洞价值」排序，前 3 名就是今天的目标
   写进目标卡（cnvd-lab/data/目标卡模板.md 就是这个用途）
```

**为什么这个动作值钱**：它把「今天测什么」从**心情驱动**（哪里有感觉点哪里）变成**地图驱动**（哪条边界最可疑打哪里）。你 27 天计划里「规模化覆盖 + 情报 + 耐心」的入口论，落到单日执行就是这 15 分钟。

## 六、新技术 = 新边界（这个模型的预测力）

模型的正确性检验：**它能推导你没学过的领域。**

- **云安全**（728 篇在智库里吃灰）= 边界从「网络 perimeter」变成「IAM 身份 perimeter」：每条 API 调用都是一次过闸，闸是 policy 文档。所以云渗透的主线不是 RCE，是**身份链**（拿到一个 key → 它能过哪些闸 → 哪个闸后面有提权路径）。
- **K8s** = 边界 ⑫ 的具体化：namespace/RBAC/ServiceAccount 是闸，容器逃逸是「闸的物理解析差异」。
- **AI 安全** = 边界 ⑪：**prompt 里指令和数据同渠道**——这是 SQL 注入的原罪在模型上重演（01 篇说过：LLM 是新汇点）。Agent 的工具调用 = SSRF/RCE 的新形态，RAG = 二次注入的新形态。
- **供应链** = 边界的「时间维度」：你今天可信的依赖，明天可能变不可信（投毒更新）。

> 所以：学新领域时别先背技法，**先问「它的信任边界在哪几条，闸是什么」**——然后去智库/上游文档查这条边界的特产漏洞。这就是 `06_成长系统/40小时速通法` 的理论根据。

## 七、练习（20 分钟，纸笔，不发请求）

1. 从雷达表挑一个**没碰过**的产品，只看它的官网介绍+文档（被动情报），画出 §五 的边界图；
2. 写下：它可能内嵌哪些寄生组件（查它的部署文档/下载它的安装包看 lib 目录——本地行为，合规）；
3. 产出前 3 优先级攻击面，预测每个的「特产漏洞」；
4. **（可选，若有授权）** 实战验证，记录命中/未命中，未命中分析是「图错了」还是「闸比想象中好」。

> **验收标准**：
> - [ ] 能默画 §二 的十二条边界并各说一个特产漏洞
> - [ ] 能用边界语言完整重述你的 JimuReport 案例（不看原报告）
> - [ ] 完成练习 1-3，目标卡入库 vault
> - [ ] 听到一个新框架/新产品时，第一反应是「它新增了哪条边界」而不是「它有什么 CVE」

> **智库检索词**：
> `未授权` 系列（对照家族清单查漏成员）· `SSRF metadata`（边界⑥）· `IDOR` / `horizontal privilege`（边界⑦，薄，查完去 HowToHunt 补）· `Spring Actuator` / `Nacos`（边界④验证细节）· `prompt injection 边界`（看 src-hunter-skill 怎么用同一模型写 AI 安全——它就是这么组织的，好源要读出结构）

## 【学习建议】

1. **本篇和你已有的 MOC-未授权访问 是同一件事的「术」与「道」**：MOC 里 8 篇是战果，本篇是战果背后的家族定理。读完后回去给那 8 篇每篇加一行「它属于哪条边界、家族里还有谁」。
2. 边界图要**画在纸上或白板工具里**，不要只在脑内过——画出来的图才能被别人（和三个月后的你）审查。vault 里建 `边界图/` 目录，一图一文件，文件名 = 产品名。
3. 别追求十二条边界全精通。**你的当前主线是 ④⑦⑩**（组件未授权 + 越权 + 寄生家族），其余保持「能识别、知道去哪查」即可——这正是智库的用法。
4. 冲刺期用法：每天【实】块开工前，花 5 分钟给当天目标重画/修订边界图。就 5 分钟，不要超时。
