# 05 · 报文即证据：不发 payload 也能看穿一个系统

> 心智模型 5/6 ｜ 与 cnvd-lab `P01_HTTP报文精读` 的分工：P01 教你**每个字段是什么**，
> 本篇教你**从字段推断出什么**——前者是识字，后者是读心。
> 对应你的 vault 笔记《找特征指纹》：那篇是直觉，这篇是方法论。

---

## 一、一句话内核

**HTTP 报文是系统在对你「说真话」——它撒谎的成本很高（要专门配置），默认状态下每一行都在泄露身世。**

专家看一个 `curl -v` 的输出，30 秒内建立目标模型：什么语言、什么框架、什么中间件、有没有 CDN/WAF、大概什么年代、开发团队什么习惯。这个模型直接决定后面测什么（02 篇的边界图第 1 步就是它）。

---

## 二、证据链：从报文到结论

### 2.1 Set-Cookie 是最诚实的证人

| 证据 | 结论 | 追加动作 |
|---|---|---|
| `JSESSIONID=` | Java 系（Servlet 容器） | 找 `/actuator`、`/druid`、`swagger` |
| `JSESSIONID` + `route=`/`SERVERID=` | 前面有 F5/负载均衡 | 会话粘滞靠 cookie——**多实例部署**，OOB/盲注结果可能落在另一台 |
| `rememberMe=deleteMe` 或长 base64 cookie | **Shiro**（deleteMe 是 Shiro 特有指纹） | 直接查 Shiro 反序列化历史（key 硬编码系列） |
| `SESSION=<base64>` | Spring Session | 解码看内容（base64 -d，**只看结构不解密**） |
| `PHPSESSID=` | PHP | 找 `.php` 后缀、`/install/`、老 CMS 指纹 |
| `laravel_session=` / `XSRF-TOKEN=` | Laravel | 查 `APP_DEBUG` 泄露面、`/_ignition/` 系列 |
| `csrftoken=` + `sessionid=` 成对 | Django | 查 `DEBUG=True`、admin 路径 |
| `ASP.NET_SessionId` / `.AspNetCore.` | .NET | `elmah.axd`、trace.axd 历史面 |
| `acw_tc=` / `acw_sc__v2=` | **阿里云 WAF/盾** | 你已经知道对面有闸了——06 篇的功课 |
| `Set-Cookie` 里带 `HttpOnly` 缺失 | 团队安全习惯弱 | 整体降低对该目标「其他地方做得好」的预期 |

### 2.2 响应头里的第二证人

| 头 | 读法 |
|---|---|
| `Server: nginx/1.x` | 半可信（常改）。**版本旧 = 团队不维护 = 其他洞概率高**——版本本身是「安全文化指纹」 |
| `X-Powered-By: PHP/7.0.x` | 2016 年的 PHP 还在线 → 老系统，找老 CMS/老框架的 N-day |
| `X-Drupal-Cache` / `X-Generator: WordPress` | 直接报 CMS |
| `WWW-Authenticate: Basic realm="..."` (401) | 设备类（摄像头/路由器/打印机）——默认口令主战场 |
| `Content-Security-Policy` 存在且严格 | 团队懂安全 → XSS 预期调低，逻辑洞预期调高 |
| `Access-Control-Allow-Origin: *` 或反射 Origin | CORS 面（06 篇细讲） |
| 头的**顺序和大小写风格** | 主动指纹（不同服务器发头顺序不同）——工具化领域（如 HTTP/2 指纹），了解即可 |

### 2.3 状态码的真实语义（和教科书不一样的部分）

| 你看到 | 教科书说 | 实际读法 |
|---|---|---|
| 302 → `/login` | 需要认证 | 可能是**网关/拦截器**干的（应用层未必校验）——**带任意假 cookie 再试一次**，有时就进去了（前端鉴权假象） |
| 403 | 禁止访问 | **谁给的 403？** body 长度小+带厂商页=WAF；body 是 nginx 默认页=中间件；body 是业务 JSON=应用。三者对应完全不同的下一步 |
| 401 vs 403 | 未认证 vs 无权限 | 分不清说明鉴权实现随意——**随意实现=越权面**（07/08 边界） |
| 405 Method Not Allowed | 方法不对 | **好消息：端点存在**，只是方法错。`Allow:` 头直接告诉你支持什么 |
| 200 + body「无权限」 | 成功 | 业务层拒绝但**接口活着**——报错文案差异常常还能枚举数据存在性 |
| 500 + 堆栈 | 服务器错误 | 金矿：框架、版本、路径、SQL 片段、有时连参数值都在 |
| 400 + 解析报错 | 请求错 | 你发的畸形请求被**谁**解析报错的？报错方=真正处理你数据的那一层（定位闸在执行链哪一环） |

### 2.4 时序证人

- 首字节时间（TTFB）稳定 ~几十 ms：可能纯静态/缓存命中。
- 特定参数让 TTFB 跳变 ±数百 ms：**后端有真实逻辑/查询在响应你的输入**——这是无回显场景的第一神谕（03 篇）。
- 全站固定延迟 3-5s：可能有 WAF 检测流水线或境外链路。
- **同一功能未登录比登录后快很多**：鉴权检查本身在耗时？还是未登录走了缓存？——缓存面（投毒）假设。

### 2.5 重定向链是业务流程的自白书

登录 → 302 到哪（`/home`? `/index?first=1`? 带不带 `redirect=` 参数）；会话过期 → 跳哪；OAuth 回调 → `redirect_uri` 白名单怎么写的（**看它拒绝你的假 uri 时的报错**，报错常泄露匹配规则：前缀匹配？包含匹配？正则？——每种规则的可绕法不同）。

## 三、请求侧：你发的每个头也是探针

| 你做什么 | 你在测什么 | 备注 |
|---|---|---|
| 加 `X-Forwarded-For: 127.0.0.1` | IP 白名单是否信任代理头 | 只读探测，合规；**很多「内网限制」就死在这一行** |
| 换 `Content-Type: application/json` ↔ `form` ↔ `xml` | 后端解析器切换 | XML 面 = XXE 候选；同一参数不同 CT 下校验是否一致（06 篇解析差异） |
| `Content-Type` 带奇怪 charset | 编码解析差异 | 转义失效的经典来源 |
| HEAD/OPTIONS/TRACE | 端点元信息 | OPTIONS 的 `Allow` 白送方法清单 |
| 参数污染（同名参数两次） | 谁取第一个谁取最后一个 | WAF 与后端分歧点（06 篇 HPP） |

> **红线提醒**：以上全部是**单请求、只读、无副作用**级别的探针，符合你的协议。爆破、压测、批量注册不在其中——那是「量层」动作，你的战场在「语义层」（06 篇结尾展开这个职业分水岭）。

## 四、指纹 → 攻击面：一张「看到什么想到什么」速查

这是 02 篇边界图第 1 步的弹药库，养在 vault（`MOC-工具速查` 或新建 `MOC-指纹推断`）：

```
Shiro (rememberMe)        → 反序列化 key 系列 + Actuator 面
Spring (JSESSIONID+whitelabel error page) → Actuator/heapdump/env、SpEL 面、/jolokia
若依 RuoYi (特定静态资源路径/登录页长相)   → 生态 N-day 清单（你雷达表主粮）
JeecgBoot (jimureport 路径存在)           → 你的成名战家族，直接进 04 篇流水线
Drupal (X-Drupal-Cache)   → geddon 系列历史 CVE 按版本对号
WordPress (wp-content)    → 插件面 >> 核心面（插件=寄生组件，02 篇家族逻辑通用！）
Nacos/Eureka (8848/8761 特征页) → 默认口令/未授权 → 配置里的数据库凭据（**只确认存在即停，红线**）
宝塔/phpstudy 面板特征     → 老版本面板 N-day
F5/负载均衡 (route cookie) → 多实例 → 盲注/OOB 结果不一致时先想到它
CDN (acw_tc / __cf_bm)    → 真实源站问题：证书透明度日志(crt.sh)、历史 DNS、全站扫描找裸 IP
```

> **注意最后一条的合规性**：源站发现属于测绘情报（只读、公开数据源），但**对源站的任何测试仍需在授权范围内**——授权书写的是域名还是 IP 段，决定了你能不能碰裸 IP。拿不准就不碰，问委托方。这条写死在你的红线速查里。

## 五、练习：盲猜游戏（每周 2 次，每次 15 分钟）

1. 随机挑 5 个网站（**公开网站，只做被动 GET 首页级请求**——这属于正常浏览行为；更稳妥的做法是用你自己部署的雷达表目标）；
2. 只看 `curl -v -s url | head -50` 的输出（状态行+响应头+body 开头），**写下**：语言/框架/中间件/CDN-WAF/系统年代/团队安全习惯评分（1-5）；
3. 允许再发最多 3 个只读请求验证你的猜测（如 `/favicon.ico` hash、报错页触发）；
4. 记录命中率。**目标：4 周内「语言+框架」命中率 >70%。**

> **验收标准**：
> - [ ] 能默写 §2.1 的 cookie 指纹表（至少 8 条）
> - [ ] 能说出「403 的三种出身」及区分方法
> - [ ] 完成 2 轮盲猜游戏，命中率记录在 vault
> - [ ] 给你任意一段 curl -v 输出，60 秒内说出「这是什么栈+第一个该测的边界」

> **智库检索词**：
> `指纹` / `fingerprint` · `Shiro rememberMe` · `actuator heapdump` · `source IP behind CDN` · `favicon hash`
> 交叉参照：vault《找特征指纹》《方法论》（Hunter/奇安信测绘语法）——把本篇 §四 的表和你那两篇合并成一张总表，挂进 MOC-资产测绘。

## 【学习建议】

1. **本篇是「被动情报」能力的地基**，正好补你质检报告里的盲区（侦察/指纹全库仅 34 篇）。外部资源：Web 指纹识别工具（wappalyzer 类）的**规则库源码**是最好的教材——看别人怎么把指纹写成规则，然后给 wappalyzer 提一条它没有的国产组件规则（合法开源贡献，还是简历素材）。
2. 训练要**限时**：30 秒建模是目标，慢慢分析谁都会。直觉=压缩的经验，压缩靠限时。
3. 和 03 篇联动：盲猜游戏本质就是「假设-验证」回路的低风险训练场——猜错无成本，实战猜错浪费授权窗口。
4. 别买/别背「指纹大全」类资料。指纹会过时，**推断方法不会**：遇到不认识的 cookie 名，你的动作是「搜它/解码它/在本地跑一个同款系统看它发什么」——这个动作序列才是资产。
