# 06 · 防御者视角：绕过是一门「解析差异」学

> 心智模型 6/6 ｜ 对应你 vault 的 `MOC-现代防护对抗`（10 篇，含那篇 0KB 的
> 《熔断，超时杀死时间盲注》——本篇 §五 就是它的正文）。
> 前置：01（数据流）、05（报文证据）。

---

## 一、一句话内核

**所有绕过，本质上只有两种：① 防御方和执行方对同一份数据的「解析不一致」（差异类）；② 防御方的规则集有「没写到的情况」（盲区类）。**

一万种 bypass payload 只是这两个机制的实例。所以别背 payload——**背机制，payload 现场推导**。这也是为什么 PATT（PayloadsAllTheThings）的正确用法是「验证你推导出的思路」，而不是「从头翻到尾碰运气」。

---

## 二、先理解防御方的流水线（知己知彼的「彼」）

一个典型 WAF/防护的处理链：

```
原始字节流
  → ① 协议解析（HTTP/1.1? chunked? HTTP/2 降级?）
  → ② 归一化（URL 解码? 几次? Unicode 规范化? HTML 实体?）
  → ③ 参数提取（按什么规则切分 body? form? JSON? 取第一个还是最后一个同名参数?）
  → ④ 规则匹配（正则/黑名单/语义分析）
  → ⑤ 动作（放行/拦截/限速/记录）
```

**后端应用也有一条自己的流水线，而两条流水线几乎必然有细节差异。** 差异出现在哪一步，绕过就长什么样：

| 差异位置 | 经典形态（概念层） | 你该做的探针 |
|---|---|---|
| ①协议层 | chunked 分块让 WAF 看不到完整 payload；CL/TE 理解不一致（请求走私的研究领域，PortSwigger 有系统教材） | 合法授权下才碰；概念理解优先 |
| ②归一化 | WAF 解码一次、后端解码两次 → **双重编码**；`%2527` 类 | 同一 payload 的 N 层编码变体，逐个试到命中 |
| ③参数提取 | 同名参数 WAF 查第一个、后端用最后一个（HPP）；`Content-Type` 声明 form 实发 JSON，WAF 按 form 解析扑空 | 双份参数探针；CT 切换探针（05 篇 §三） |
| ④规则层 | 正则只防了 `union select` 没防 `union/**/select`；黑名单漏了同义函数（`substring`→`mid`→`substr`） | 等价替换矩阵：一个语义 N 种写法 |
| ⑤动作层 | 拦截但**不回滚**（请求已到后端）；限速但换个端点重新计数 | 观察拦截时机与后端日志（有权限时） |

> **学习建议**：这张表值得抄进 vault `MOC-现代防护对抗` 顶部当总纲。你已有的 10 篇对抗笔记，每篇往表里归类——归不进去的就是新知识，归进去的就有了「为什么有效」的解释层（搬运→消化的又一次转换）。

## 三、防御强度是「层次」不是「有无」：四级对抗阶梯

遇到防护时，先判断它在哪一级，再决定投入（时间盒纪律，03 篇 §六）：

| 级 | 防御形态 | 特征识别 | 你的策略 |
|---|---|---|---|
| L0 | 无防护 | 报错直出、payload 原样回显 | 常规打法，注意别打崩（红线） |
| L1 | 静态规则（黑名单正则） | 特定关键字 403、拦截页带厂商名 | **差异类+等价替换**，成功率最高的一级 |
| L2 | 语义分析型 WAF（libinjection 类） | 变形 payload 也拦、但非关键字触发 | 找**语义边界**：合法业务里必然存在的「像攻击」的模式（如搜索框天然含引号）→ 从业务合法输入切入 |
| L3 | RASP（应用内 hook） | 命令/SQL 在**执行函数处**被拦，变形无效 | 换执行通道：让**数据库/系统自己**干活（存储过程、DB 端函数、计划任务类特性）——概念层理解即可，全部动作限授权+靶场 |
| L4 | 行为/风控（速率、指纹、人机） | 单请求全放行，频率一高就验证码/封禁 | **不硬抗**。你的红线本来就禁止爆破压测——L4 目标只做低频精准测试，把战场拉回语义层 |

**判断防护级别只要 3-5 个探针**：无害 canary → canary+单引号 → canary+关键字 → 变形关键字 → 频率微增。五个请求画出对面的防御画像（合规版「防护指纹」，进目标卡）。

## 四、反读防御文档：CheatSheets 是「攻击面说明书」

grimoire 里 161 篇 OWASP CheatSheets 是**防御方的规范文本**。反着读它：

```
每一条 "SHOULD / MUST"  →  现实中大量系统没做到或做错  →  一个检查项
每一条「常见错误」小节   →  直接就是你的假设清单
```

示范三个（全部可在授权目标上做只读检查）：

| CheatSheet | 规范说 | 现实常见错法 | 你的探针 |
|---|---|---|---|
| JWT | 校验 `alg`，拒绝 `none`，密钥强度足够 | `alg` 信任客户端、RS256→HS256 混淆、`kid` 拼接注入、弱 secret | 拿公钥改 token 重放（**只在授权范围**）；`jwt_tool` 类工具在本地靶场练 |
| CORS | Origin 白名单精确匹配 | **反射任意 Origin**、`null` 放行、前缀/后缀匹配（`evil.com.target.com` / `target.com.evil.net`） | `Origin: https://example.org`（无害域名）看 `ACAO` 是否反射 |
| 文件上传 | 服务端校验类型+重命名+隔离目录 | 只校验 `Content-Type` 头、只 blacklist 后缀、上传目录在 web 根且可执行 | 传 `.txt` 观察：存储路径回显？文件名处理规则？——**到此为止，红线内不传可执行物** |

> **这就是「防御知识→攻击面」的转换装置**。你以后读任何安全规范（等保、开发规范、云安全基线）都用这个读法：**规范 = 攻击者 checklist 的补集**。

## 五、给那篇 0KB 笔记的正文：熔断、超时与「信道战争」

你自己撞出来的洞察——「熔断，超时杀死时间盲注」——值得升格成一条**一般规律**：

> **防御方可以杀死你的「神谕」（03 篇），而不只是杀死你的 payload。**

对照表：

| 防御手段 | 杀死的神谕 | 你换什么神谕 |
|---|---|---|
| 查询超时/熔断（sleep 5 → 连接 2s 就被掐） | 时延 | **布尔**（真假条件内容差）→ 不行再**报错**（`extractvalue` 类）→ 再不行 **OOB**（DNS 带外，不受响应超时影响） |
| 统一错误文案 | 报错文本 | 内容 diff（页面其他部分是否随输入变化）、时延微差 |
| 响应长度固定/ padding | 长度 | 时序侧信道、OOB |
| 出网封禁（DNS/HTTP 全拦） | OOB | **站内二次信道**：数据写进了哪里？导出文件？邮件通知？站内信？管理后台日志页？——「数据总要落地，落地处就是信道」 |
| 验证码/风控（频率触发） | 高频探测本身 | 降频+精准假设（03 篇触发器表的价值就在这：**每次请求都要值回票价**） |

**信道战争三原则**：

1. **永远准备第二、第三神谕**。开工前就问「如果时延被杀我用什么」——不要现场慌乱翻 payload 大全。
2. **被杀的神谕本身是情报**：能掐超时说明有中间层在管连接（网关/连接池/WAF 主动防御）→ 更新 02 篇边界图。
3. **站内信道最容易被忽视也最合规**：让数据落到「你有权查看的页面」（自己的账号后台、自己的导出文件），全程无出网、无副作用——这是红线内的最优解。

> 把以上内容合并进你那篇空笔记，标题改成《信道战争：当防御方杀死你的神谕》，挂进 MOC-现代防护对抗。**你的第一手战场经验 + 这层解释框架 = vault 里第一张真正的「消化型」对抗卡。**

## 六、练习：自己当一次防御方（2 小时，本地，一次性根治「只会绕不会防」）

绕过技术学不深的根本原因是没当过防御方。练习：

1. 本地 docker 起 nginx + ModSecurity(CRS) 或 Go 的 Coraza，后面挂一个你自己的含 SQLi 的小应用（Flask 十行就够，或用 vulhub 现成环境）；
2. 用你熟悉的注入打它，记录：哪些被拦、**拦截日志里命中的规则 ID 和正则是什么**；
3. 针对每条命中的规则，用 §二 的差异/等价思路推一个绕过，验证；
4. 产出一张「规则 → 绕过 → 原理归类（差异类/盲区类）」对照表，进 vault。

> 这个练习做完，你看 WAF 的眼神会永久改变：**从「一堵墙」变成「一组我可以逐条理解的规则」**。这也是 CNVD/SRC 报告里「修复建议」质量的来源——你能说出「为什么加这条正则不够」。

> **验收标准**：
> - [ ] 能说出绕过的两大机制并各举两例
> - [ ] 能用 5 个探针判断目标防护级别（L0-L4）
> - [ ] 那篇 0KB 笔记已重写为《信道战争》并挂 MOC
> - [ ] 完成本地 WAF 对抗练习，产出对照表 ≥5 行
> - [ ] 能用「反读法」从任一 OWASP CheatSheet 提取 ≥3 个检查项

> **智库检索词**：
> `WAF bypass` · `HPP` · `double encoding` · `request smuggling`（只读概念，实践必须授权+靶场）· `RASP` · `libinjection` · `CORS misconfiguration` · `JWT algorithm confusion`
> 外部补充：PortSwigger Research 博客（走私/解析差异的一手研究，grimoire 的 portswigger-notes 只有 lab 答案，研究文章要在线看）

## 【学习建议】

1. **本篇优先服务你的既有资产**：先做 §五（把空笔记补成对抗卡，30 分钟），再做 §六（2 小时练习）。§二§三§四当参考手册用，实战遇到防护再回来精读对应节。
2. 对抗知识的半衰期最短（规则天天更新），所以**只深学机制层**（差异/盲区/信道），实例层永远现场查智库——这是六个模型里「智库依赖度」最高的一篇，设计如此。
3. 合规即专业：本篇所有动作都停在「单请求、只读、可解释」级别。L3/L4 的深水区（走私实战、RASP 绕过实操）留给授权红队场景和有监督的靶场，**自学期不碰**——这不是胆小，是让你能一直干下去的职业寿命设计。
4. 至此六个模型闭环：**01 看河（数据流）→ 02 画闸（边界）→ 03 走路（假设回路）→ 04 繁殖（泛化家族）→ 05 读心（报文证据）→ 06 拆墙（对抗）**。下一目录 `03_训练回路` 把它们变成每周的训练菜单。
