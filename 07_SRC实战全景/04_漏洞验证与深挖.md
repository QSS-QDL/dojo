# 04 · 漏洞验证与深挖（20 情境）

> 阶段定位：「疑似有洞」到「证据完整、影响讲清、可以提交」之间的全部坑。
> 本篇的最高纪律：**验证深度 = 证明所需的最小深度**。多一分都是风险，少一分都会被驳回。

---

**§1 疑似 SQL 注入但不确定**
- 症状：加引号报错/页面变化，但复测又不稳定。
- 病因：三种假阳性——页面本身动态（时间戳/推荐位）、报错与输入无因果、CDN 缓存捣乱。
- 处置：**对照实验法**（你 JimuReport 报告的看家本领，标准化）——①同一请求重放 3 次确立基线（响应哪些部分天然波动）；②真假条件对照：`and 1=1` vs `and 1=2`（语义等价于原请求 vs 改变查询结果），差异稳定复现 ≥3 次才算数；③报错型直接看报错内容是否随输入语法变化（`'` 和 `"` 报不同的错=强证据）；④换参数位置交叉（GET 不行试 POST 同名参数/Header/Cookie）。
- 止损线：对照实验 30 分钟仍不稳定 → 记录「疑似+现象」进目标卡，挂起。**不稳定的洞提交=被驳+扣信用分**，宁可晚不可错。

**§2 盲注无回显**
- 处置：神谕优先级从高到低逐个试——**报错**（`extractvalue`/`updatexml`/整数溢出类，一次请求一比特以上，最快）→ **布尔**（真假条件的内容差，需要页面有稳定差异点）→ **时延**（注意熔断：dojo 06 篇 §五，超时防御会杀它）→ **OOB**（DNS 带外，出网封了就没戏，03 篇 §12）。每换一个信道先做一次「信道可用性验证」（如时延先测 `sleep(3)` 是否真的慢 3 秒），再开始取数。
- 止损线：证明「可注」只需要**取出当前数据库用户或版本号的 1-2 个字符**——不要拖库证明（红线+无必要），报告写「已验证可注入并读取系统变量，未获取业务数据」。

**§3 越权看起来像，但不确定算不算漏洞**
- 症状：改 ID 能看到别的东西，但那东西「好像本来就是公开的」？
- 处置：三问定性——①**数据敏感性**：看到的内容含个人信息/交易/内部字段吗（含=成立）；②**访问预期**：正常业务流程中这个数据只该谁看（前端要登录才展示=有访问控制预期=后端不校验就是洞）；③**对照路径**：无凭证直接请求同一接口能拿到吗（能=未授权访问，比越权更硬）。三问有一个「是」就成立，按最高的那个定性写报告。
- 学习建议：「公开列表页」和「越权看详情」的边界感是逻辑洞第一功力——把你 MOC-未授权访问 8 篇按这三问重新标注一遍，半天时间，功力立涨。

**§4 IDOR 存在但打不出数据**
- 症状：ID 可预测、接口无鉴权提示，但返回空/404。
- 病因：ID 对了但**状态/归属/租户**不对（软删除、跨租户隔离、需要配套参数）。
- 处置：①换 ID 空间（顺序 ID 不行试雪花 ID 的低位遍历？不——雪花 ID 不可遍历，换思路）：从**自己的**合法数据里找 ID 生成规律（创建时间戳嵌入？前缀？）；②找**泄漏 ID 的旁路**：列表接口/搜索接口/分享链接/导出文件/邮件通知里的 ID；③配套参数补齐（`?userId=` 之外还要 `tenantId`/`orgId`——从自己账号的合法请求里抄结构）；④试**批量端点**（`/batch?id=1,2,3` 类接口常漏校验单条归属）。
- 止损线：拿到自己两个账号间的越权证据即可提交，不需要证明「全量可遍历」。

**§5 XSS 只能打自己（self-XSS）**
- 症状：注入点存在，但只 reflected 在「我自己提交的请求」的响应里。
- 病因：self-XSS 不构成漏洞（无法攻击他人），平台必驳。
- 处置：找「让别人触发」的路径——①**URL 可控反射**（链接发给受害者即触发=reflected XSS 成立，验证到 payload 执行于你构造的 URL 即可，**不真的去发别人**）；②**存储面**（内容会进入他人视图：评论区/昵称/文件名/自定义字段——见 §6）；③**组合升级**：self-XSS + 登录 CSRF（强制受害者带 payload 登录）或 + 账号绑定流程=可接管，组合链按最高环评级；④CSP/防护现状记录进报告（影响修复建议质量）。
- 止损线：三条路都不通 → 老实记录 self-XSS，不提交（或按平台细则作为「风险提示」类低危提，别抱期待）。

**§6 存储 XSS 没人触发**
- 症状：payload 存进去了，但没有受害者视角的触发。
- 处置：①**证明存储+证明渲染面**即成立：截图「输入存储成功」+「另一浏览器/另一账号访问时 payload 执行」——第二账号用你自己注册的小号，完全合规；②渲染面是**管理后台**的话：报告注明「需管理员审核内容时触发，可致后台沦陷」——多数平台按存储 XSS 高危收，不需要你真的等管理员上钩（也不要构造钓管理员的实战页面，证明到小号互打为止）；③渲染在导出/邮件/打印视图的：同样用双账号自证。
- 止损线：全库找不到任何第二人可见的渲染面 → 降级为 self，回 §5。

**§7 SSRF 只能访问本机**
- 症状：`url=` 参数只能请求 `127.0.0.1`，外网不通。
- 病因：这不是失败——**内网可达性本身就是价值**。
- 处置：本机=内网的入口——①探本机服务清单（Redis 6379/MySQL 3306/memcached 11211/ES 9200/各管理端口，**低频逐端口**，每个端口一次请求）；②云环境探 metadata（`169.254.169.254`，IMDSv1 可达=高危证据，取到「存在」即停）；③协议面（`file:///etc/passwd` 一次尝试=文件读取升级；`gopher://`/`dict://` 可用性探测——gopher 打内网 Redis 写 crontab 类属于**改变状态的动作，只写到「协议可用」为止，不执行写入**）；④内网段测绘证据（10.x/172.x/192.168.x 的响应差异表）。报告影响链：「可探内网→可达 metadata/Redis→潜在横向」。
- 止损线：协议升级尝试各一次，不重复；内网探测总请求数控制在两位数。

**§8 文件上传被拦**
- 症状：后缀/内容/MIME 层层校验。
- 处置：验证的深度阶梯（到哪层停看证据强度）——①**前端校验**：抓包改后缀成功=证据成立（用无害标记文件如 `test.txt` 改名 `test.png` 内容仍是文本，或平台允许的最小证明物；**不传 webshell**，传了也是「能上传」不需要「能执行」，执行验证看 §8③）；②**内容校验绕过**：图片马+文件包含组合（有 LFI 面才成立，单独图片马多数平台不收）；③**执行验证**：上传目录是否在 web 路径+是否解析（访问已上传的标记文件 URL：能访问且返回内容=存储型风险成立；能否执行脚本语言——**用输出 phpinfo 类信息页替代一句话木马**，多数平台认可且危害可控）；④SVG/HTML 上传=存储 XSS 面（§6 双账号自证）。
- 止损线：证明「可上传+可访问」即停，不做「可执行任意代码」的深度验证（那一步的边际评级收益低、边际风险高）。

**§9 反序列化找不到链**
- 症状：入口确认（`rememberMe`/`viewState`/magic bytes），但打不出 RCE。
- 处置：①**存在性证明不需要 RCE**：URLDNS 链（只触发一次 DNS 解析，无害）打通=「存在反序列化入口且可触发出网」，多数平台按高危/中危收——这是标准的最小证明；②找链三路：依赖清单（jar 包列表从报错/备份/`.git` 泄露拿）→ ysoserial/库内链匹配（grimoire `反序列化` 45 篇）→ 补丁 diff 反推厂商修过的链（dojo 04 篇）；③**key 类问题**（Shiro）：默认 key 清单一次轮试属于常规检查（每个 key 一次请求），非爆破。
- 止损线：URLDNS 证明完成即报告；实链 RCE 验证只在本地同版本环境做（红线：利用链触发不进生产）。

**§10 逻辑洞证明不了危害**
- 症状：「验证码可绕过」但平台说无影响。
- 病因：逻辑洞的危害不在动作本身，在**动作的业务后果**——报告没把后果链讲出来。
- 处置：影响链叙事模板（05 篇 §4 详展）：`缺陷动作 → 业务后果 → 可规模化程度 → 资损/数据/声誉影响`。例：验证码可复用 → 可批量注册/批量发短信 → 按目标日活估算短信费用与垃圾账号规模 → 运营资损+数据污染。**估算用公开数据**（备案量/下载量/页面自称用户数），不实测规模化（实测=攻击）。
- 止损线：后果链讲到「规模化可能性」为止，永远不真的规模化。

**§11 竞态跑不出来**
- 症状：怀疑并发洞（优惠券/余额/签到），单线程测不出。
- 处置：①**最小证明原则**：两个自己的账号+一次双请求并发（single-packet attack 或 Burp turbo 类**单次**并发组），成功一次即证据，**不循环刷**（循环=薅真实资损=破坏业务红线）；②跑不出的常见原因：后端有锁/幂等键（这是好事，说明修了，记录进案例卡「该厂商有此防护」）；请求到达时间差太大（换同连接多路复用）；③本地搭同款逻辑验证「该代码模式确实可竞态」，报告引用（本地实验+线上疑似证据的组合报告，平台多数认可）。
- 止损线：线上并发尝试总次数 ≤3 组。证明不了就写「疑似+本地复现」，标注未在线上确认。

**§12 危害评级上不去**
- 症状：你觉得高危，平台评中危/低危。
- 处置：评级是「影响面×可利用性」的函数，上不去通常是影响面没讲透——见 05 篇 §3（降级应对全套）。技术侧自查：能不能补一个「影响升级证据」（如：未授权→拿到了什么级别的数据样本；SSRF→metadata 可达证明；XSS→打到了管理面渲染）。**补证据，不补情绪**。

**§13 洞在，但影响面小**
- 症状：确凿的洞，但数据不敏感/用户量少。
- 处置：①照提——低危单也是平台信用分和数据点，积少成多；②**泛化找影响面**（dojo 04 篇闻一知十）：这个洞在同家族其他部署是不是影响面更大？小洞常常是大家族的小样本；③报告里诚实写影响面，**别夸大**（夸大会被审核员标记，损害你后续所有报告的可信度——信用是 SRC 的隐形资产）。

**§14 一个洞扩成一片**
- 处置：固定动作四问（dojo 04 篇 §一）：模式是什么/还长在谁身上/怎么机械化检测/上游修了没。**每个洞提交前先过四问**，把「一次发现」变成「雷达表 N 行+案例卡一张+检测脚本一段」。这是你的 CNVD 通用型产能的来源，别提交完就忘。

**§15 数据拿到了，何时停**
- 症状：越权/注入已可读取业务数据，「再多拿点证据更硬」的冲动。
- 处置：**单条即停**铁律（01 篇 §14 的现场版）：一条样本证明可访问性 → 截图打码 → 本地原始数据当天脱敏归档或销毁 → 报告写「验证性获取 1 条，已删除，未批量访问」。冲动的代价是不对称的：多拿 100 条对评级毫无增益，对法律风险是质变（侵犯公民个人信息罪的入罪门槛按条数算）。
- 这一条没有止损线，是禁令级。

**§16 证据怎么留才有效**
- 处置：证据五件套标准——①**完整请求-响应对**（raw 格式，含时间戳头和 Cookie 打码）；②**复现步骤编号**（§17）；③**关键截图**（URL 栏+系统时间可见，或录屏——竞态/时序类必须录屏）；④**哈希**（涉及文件的附 sha256）；⑤**测试账号说明**（哪两个小号、归属你本人）。当天归档进 vault（脱敏后），平台提交用副本。**证据的完整性决定申诉的成败**（05 篇 §2）。

**§17 复现步骤写不清**
- 症状：审核员评论「无法复现」。
- 处置：复现步骤的黄金标准=**陌生安全工程师照抄能过**：前置条件（需要什么账号/环境）→ 每步一个动作（贴 raw 请求，标出改哪个字段）→ 预期响应（贴关键响应片段，标出看哪里）→ 成功判据（「看到 X 即证明 Y」）。自查方法：把步骤喂给 AI 审计搭子（dojo 04_AI私教 角色 4 变体）问「照这个能复现吗，缺什么信息」——AI 是最好的「陌生审核员」模拟器。
- 学习建议：你 JimuReport 报告的 59 页面穷举+对照实验就是黄金标准的样子——把那篇当模板挂进 vault 报告模板旁边。

**§18 环境差异导致不可复现**
- 症状：你测的时候能复现，审核员测不能。
- 病因：状态依赖（你的账号状态/缓存/时间窗）或对方已静默修复。
- 处置：①报告注明**时效性证据**（你的复现录屏+时间戳，证明「提交时存在」）；②列明依赖条件（「需登录态」「需从 X 入口进入」「响应缓存 5 分钟内」）；③若疑似已被修：礼貌说明「测试窗口为 X 日，如已修复请以当时证据为准」——多数平台按提交时间点的状态评级。
- 止损线：申诉一轮不认 → 接受（除非证据五件套齐全且明显误判，见 05 篇 §2）。

**§19 洞被别人抢了（重复提交）**
- 症状：平台判「重复漏洞」。
- 处置：①查判重规则（多数平台=首个有效提交者得赏，后来者 0 分或安慰分——规则原文引用）；②如果你的洞**路径不同**（不同接口/不同参数实现同一影响），申诉主张「非同一漏洞」：并排对比两份的技术差异点；③接受结果时的收获：记录该目标的「热门洞型已被覆盖」情报，下次选题避开（重复判定数据是你的选型输入）；④**根本解法是速度**：发现→验证→提交压到当天（你的 27 天计划「随时成熟随时提交」原则就是防这个）。
- 止损线：路径确实相同 → 不申诉，浪费的信用分比赏金贵。

**§20 发现打错了目标**
- 症状：测试中意识到当前资产不在授权清单（打错了旁站/客户给错了清单）。
- 处置：01 篇 §11 全套（立即停→记录→主动报告→等指示），外加：**已获取的数据全部封存待指示**，不自行「删了当没发生」（删除也可能被取证看到，封存+报告才是干净的处理）。

## 【本篇学习建议】
1. §1 对照实验、§15 单条即停、§16 证据五件套、§17 黄金标准——**这四条是你每次出洞的固定动作**，做成提交前 checklist 贴在报告模板头部（cnvd-lab docs/05 模板可直接加）。
2. 本篇和 dojo 02 心智模型的对照使用法：04 篇各卡是「症状→动作」，动作背后的「为什么」在 01 数据流/03 假设驱动/06 信道战争里——每用一张卡，回看一眼对应模型的那一节，卡就开始长在你身上了。
3. 你的现状针对性：§3/§4（越权类）和 §10/§11（逻辑类）是智库最薄+你笔记最少的区域——本篇这四卡+HowToHunt 对应章节，就是你的补课清单。
