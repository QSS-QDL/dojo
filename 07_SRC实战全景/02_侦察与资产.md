# 02 · 侦察与资产（20 情境）

> 侦察的目标不是「收集多」，是**把资产变成带优先级和边界图的作战对象**（dojo 02 边界地图）。
> 全程纪律：只读、低速、可解释——你的侦察流量要经得起对方安全团队回看日志。

---

**§1 子域名枚举无果**
- 症状：常规工具跑完只有 www 和 mail。
- 处置：五源交叉，一个不落——①证书透明度（crt.sh / censys 证书库：新系统必先签证书，**这是最难被隐藏的源**）；②自建字典 DNS 爆破（行业词+拼音+缩写+年份：`oa/erp/crm/test/dev/uat/pre/gray/beta/2024/2025`，国产系统加 `xk/yw/bmzt` 类拼音缩写）；③被动 DNS（VirusTotal/SecurityTrails 历史解析）；④搜索引擎 `site:` + 备案主体名变体；⑤**同主体 ICP 备案反查**（备案单位名下的全部域名，含已注销备案但仍在解析的）。
- 止损线：五源跑完还是空 → 这个主体的 Web 面就是小，转去打「已有资产的深层」（§4），别在枚举上加时。

**§2 测绘平台查不到目标**
- 病因：FOFA/Hunter/Quake 覆盖有偏，小单位/新资产常缺。
- 处置：测绘平台是「别人的缓存」，查不到就自己造第一手数据：§1 五源 + 对授权 IP 段低速端口普查（top1000，速率控制在对方无感级别）。**查不到本身就是情报**：没被测绘覆盖=没被同行批量扫过=处女地概率高。
- 学习建议：把你 vault《方法论》里的 Hunter/奇安信语法表和本篇合成一张总表挂 MOC-资产测绘。

**§3 IP 段归属混乱**
- 症状：一个 C 段里混着目标和非目标（托管/合租）。
- 处置：WHOIS+备案+PTR 三重确认归属；**归属不明的 IP 一律不碰**（打错目标的法律后果见 01 §11）。段内确认属于目标的资产单独入雷达表并标注「共享段——动作限速降级」。

**§4 找到的全是静态站**
- 症状：枚举出 30 个域名，28 个是 nginx 静态页。
- 病因：静态站是「正脸」，攻击面在侧脸。
- 处置：对每个静态站查五样：①历史备份（`.zip/.bak/.tar.gz/备份文件名+年份`，只试常见命名不爆破）；②`.git/.svn` 泄露（一次 GET 即知）；③JS 里提取的 API 域名（静态站的前端往往调用另一个域的接口——**接口域才是真目标**）；④历史快照（web.archive 看这站三年前长什么样，老版本路径可能还活着）；⑤同 IP 反查域名（旁站）。
- 止损线：五样都空 → 标记「已尽调」，撤。

**§5 全端口都是 CDN**
- 症状：80/443 全是云盾特征头（05 篇 §2.1 的 acw_tc 类）。
- 处置：找源站四路——①历史 DNS 解析（接入 CDN 前的 A 记录）；②证书 SAN 列表里的兄弟域名（常有直连的）；③**邮件头**（注册/找回密码邮件的 Received 链常暴露源站 IP——用你自己邮箱触发，完全合规）；④全站特征反查（favicon hash/body 特征在测绘引擎搜非 CDN IP）。**合规注意**：源站 IP 是否在授权内看授权书写法——「授权域名」通常指域名解析到的资产，源站属同一系统可测；「仅授权列表内 IP」则源站不在列表=不碰。拿不准回 01 §10。
- 止损线：四路都找不到源站 → 接受现实，正面打 CDN 后的应用层（语义层战场，06 篇）。

**§6 指纹识别不出**
- 症状：wappalyzer 类全空，报错页也被定制了。
- 处置：三步——①被动细指纹（dojo 05 篇：cookie 名/头顺序/404 页字节级特征/JS 打包命名）；②**行为指纹**：故意发一个畸形请求看谁报错（框架报错页就算定制，状态码语义和响应时序还是框架的）；③终极手段：**本地部署同款猜测**（雷达表工作流）——把候选框架各起一个，用同一组请求对比响应特征，逐一排除。自研系统则放弃「框架指纹」，转打「通用组件指纹」（它总得用 nginx/redis/某登录组件——寄生组件逻辑，dojo 02 篇）。
- 学习建议：每次「识别不出→最终识别出」的过程写成指纹卡进 vault，这是你 46 篇测绘笔记最该长的方向。

**§7 后台入口找不到**
- 症状：主站只有前台功能，后台路径字典扫不出（也不该爆破扫）。
- 处置：六个正路——①前端 JS 里的路由表和 API 前缀（`/admin/api`、`/manage` 常写在 JS 里）；②公众号菜单/小程序（后台的移动版入口常更松）；③APP 反编译（strings 过滤 url，管理端域名常硬编码在内）；④招聘 JD（「维护 xx 后台」暴露系统名和路径习惯）；⑤同主体其他站的页面脚注（「Powered by」+ 版本号 → 搜该产品默认后台路径）；④⑤是纯 OSINT，零请求成本。
- 止损线：六路皆空 → 该系统可能真没有独立后台（纯 API 服务），改打 API 面（03 篇）。

**§8 JS 文件太多读不完**
- 症状：webpack 打包出 200 个 chunk。
- 处置：**不读，抽**——①先找 `.map`（source map 没删=源码直接还原，这是 JS 分析最大的一票）；②批量下载后 grep 四类高价值串：API 路径（`/api/`、`fetch(`、`axios`）、密钥特征（`ak/sk/appid/secret/token=` + 长随机串）、内部域名（`.local`、`.inc`、IP 直连）、危险函数（`eval`、`innerHTML`、`postMessage`）；③chunk 命名规律（`chunk-admin.*.js` 这种名字就是路标）。产出物是**接口字典+密钥清单**，不是「读过 JS」。
- 止损线：抽取脚本写完就跑，人肉逐文件读 JS 超过 1 小时=方法错了。

**§9 加密参数看不懂**
- 症状：关键参数是 `sign=8f3a...` 类密文，改一位就报签名错误。
- 处置：分难度处理——①先确认**是否所有接口都加密**：老接口/回调接口/导出接口经常没跟上加密改造（打旧不打新）；②值得攻坚时：浏览器 XHR 断点定位加密函数（DevTools → Sources → XHR breakpoint），读懂算法后本地重放（Python 重写签名）；③小程序/APP 的加密在包里，反编译同样定位。**签名≠鉴权**：就算破不了签名，观察哪些接口「签名错也返回业务错误」能推出后端逻辑。
- 止损线：签名攻坚超过 4 小时无进展 → 挂起（06 篇时间盒），去打没加密的面；加密接口留给有 Frida 环境时再说。

**§10 接口没有文档**
- 处置：四路造字典——①Swagger/Knife4j 默认路径一把试（`/swagger-ui.html`、`/v2/api-docs`、`/doc.html`，未授权文档泄露本身就是洞）；②GraphQL 端点发 introspection 查询（开了 introspection = 全 schema 白送，这本身常是中危）；③前端代码反推（§8 的接口字典）；④REST 语义爆破（对已知资源名试 CRUD 变体和兄弟资源：有 `/api/order/list` 就试 `/api/order/export`、`/api/order/detail`、`/api/user/list`——**语义字典小而准，不是路径大字典**）。

**§11 APP 与 Web 不同源**
- 症状：Web 面打不动，但发现有官方 APP。
- 处置：APP 是「时光机」——后端要为老版本 APP 兼容旧接口，**旧接口=低防护面**。流程：官方渠道下载 APK → 反编译提取全部 URL/接口 → 对照 Web 接口找差集（APP 独有的接口重点看）→ 抓包看签名与鉴权（模拟器+代理证书；遇证书固定先评估成本，见 §9 止损逻辑）。注意：只逆向分析**官方包**，不碰分发渠道和二次打包物。
- 止损线：加固壳（爱加密/梆梆类）拆解成本高 → 只做 strings 级提取，脱壳攻坚不值得（除非该生态是你的主粮）。

**§12 小程序抓不到包**
- 处置：微信小程序=Web 技术栈，抓包三选一：①安卓机装证书+代理（最通用）；②PC 端小程序（缓存目录里能翻出 wxapkg，反编译出源码——**小程序反编译比 APP 容易一个量级**，接口字典直接到手）；③开发者工具调试模式（需要测试号，成本高不推荐）。高频战果：小程序后端接口无鉴权/弱鉴权（开发者假设「小程序里点不到就没风险」——这是 02 篇边界地图⑦⑧的经典失守）。

**§13 历史资产与快照**
- 处置：三个时间机器——①web.archive.org（看老版本页面里的老接口/老后台路径，**然后验证它们今天是否还活着**：退役系统未下线=无人维护=洞的保留地）；②历史 DNS（找曾经解析过的 IP/域名）；③GitHub/Gitee 历史 commit（搜公司名/域名，看离职员工提交的内部代码——只看不联系）。
- 学习建议：「还活着的老系统」是你的未授权访问家族最肥的猎场，雷达表加一列「资产年代」。

**§14 GitHub 泄露搜不到**
- 病因：搜索语法太泛，或搜错了平台。
- 处置：语法精确化——公司名中英文+域名后缀+产品名逐个搜；搜 AK 特征前缀（各云厂商 AK 有固定前缀）；**Gitee 和 Docker Hub 单独搜**（国内团队泄露在 Gitee 的比例高于 GitHub；Docker Hub 上推过的镜像里常含配置和密钥）；搜 npm/maven 发布的内部包（package 名带公司缩写的）。搜到密钥的处置：验证有效性（只验证「是活的」，不取数据）→ 按平台规则提交「敏感信息泄露」。
- 止损线：语法组合搜完无果 → 该主体代码卫生好，此路关闭，季度后复查（新员工入职会带新泄露）。

**§15 邮箱与员工情报**
- 处置：用途严格限定为**OSINT 侧写**：邮箱格式（`姓全拼@` / `首字母+姓@`）帮你理解组织命名习惯→反哺 §1 的子域字典和产品命名猜测；员工技术博客/CSDN/掘金文章常透露内部技术栈（「我司用 xx 框架」→指纹线索）。**不做**：邮箱口令猜测（红线，且基本无效）、社工钓鱼（超出白帽 SRC 边界，涉刑）、骚扰员工个人。

**§16 资产太多存不下**
- 症状：各种工具输出堆满文件夹，下次开工找不到上次进度。
- 处置：资产只有进了**带状态机的雷达表**才算存在：`新发现 → 已指纹 → 已画图(边界图) → 测试中 → 挂起(原因) → 已提交 → 已收款 / 已尽调关闭`。工具输出是原料不是资产（cnvd-lab 雷达表加状态列；dojo templates/边界图 一目标一文件）。每周五花 20 分钟做表卫生：关闭死行、更新状态。

**§17 差分监控没变化**
- 病因：你监控的是「老资产的变动」，而钱在「新资产的出现」。
- 处置：监控重心改三路：①证书透明度日志的新签发（每天新增证书=新系统上线的第一信号）；②备案新增；③目标公众号/小程序的新发布。**新上线 72 小时是黄金窗**（还没进安全团队的巡检名单）。老资产月度复查即可。

**§18 目标突然下线**
- 处置：先分辨——「被修下线」（你或别人报过洞后消失：等它回来，**修复后重上线的系统常修得不完整**，回来就是你的复查窗口）vs「业务下线」（永久消失：雷达表关闭该行，同系统的兄弟资产还在的话转移过去）。分不清就每周探一次，连探 4 周无果关闭。

**§19 侦察被察觉**
- 症状：测试中收到对方警告/账号被封/IP 被临时拉黑，或委托方问「你们是不是在扫我们」。
- 处置：①立即暂停该目标全部动作；②自查流量画像（你是不是把扫描跑出了 DDoS 的节奏？——回 dojo 03 篇最小探针纪律）；③如实向委托方说明动作范围和目的（你有授权，怕什么；心虚的响应只会升级事态）；④整改方法后降速重启。被察觉不是事故，**被察觉后隐瞒或加速才是事故**。

**§20 信息很多但建不起目标模型**
- 症状：侦察做了一堆，说不清「这个系统到底是什么架构、该从哪打」。
- 病因：信息没有骨架。
- 处置：强制执行 dojo 02 篇 §五 的 15 分钟边界图动作——纸上画出请求路径的每一跳和十二条边界状态，侦察信息各归其位。**画不出来的部分就是下一步侦察的精确目标**（图上「未知」格子=待办清单）。侦察的终点不是数据量，是一张能指出「先打哪」的图。

## 【本篇学习建议】
1. 本篇是**工具箱思维**：20 个情境=20 组动作组合。别背，实战遇到对应症状时回来查，用过 3 次的自然记住。
2. 把 §1/§5/§8/§10 的四组「多源交叉」动作固化成你的侦察 SOP 清单（cnvd-lab A1 的工程化补充），每个新目标机械执行一遍——侦察质量靠流程保底，不靠灵感。
3. 侦察的所有产出当天进雷达表/边界图（§16 纪律），否则一周后等于没做。
