# 03 · 入口与打点（18 情境）

> 阶段定位：侦察画完边界图之后，「从哪里进、进不去怎么办」。
> **总纪律**：SRC 场景的终点是**漏洞证明**，不是控制——绝大多数情境到「证明可进入」就停手写报告。
> 深度渗透动作（横向/持久化）只属于有明确授权的 HW/红队项目，且遵守你签过的红线协议。

---

**§1 所有端口都试了，没有入口**
- 症状：top1000 端口全关/全滤，Web 只有一个铁板登录页。
- 处置：入口不在「端口」维度找，换四个维度——①**协议维度**：主域没有，子域/兄弟系统有没有（回 02 §1 五源）；②**端维度**：Web 没有，APP/小程序/公众号有没有（02 §11-12，移动端历史接口常是软肋）；③**人维度**：员工暴露的配置/代码泄露里有没有内部入口（02 §14）；④**时间维度**：现在没有，历史快照里有没有还活着的老入口（02 §13）。
- 止损线：四维各扫一遍仍无入口 → 这个目标的 perimeter 是真硬，雷达表标「硬目标-季度复查」，主力撤。硬磕铁板是新手时间黑洞第一名。

**§2 只有一个登录页**
- 症状：全部攻击面=一个登录框。
- 处置：登录页五连测（全部单请求级、低频）——①**注册口**：能注册就有内面（注册后世界大得多）；②默认账号（admin/admin 类**一次尝试**，不是爆破——一次默认口令尝试属于常规安全检查，多次就是爆破，触你的红线）；③找回密码流程（用户名枚举/验证码回显/重置链接可预测——逻辑洞高发区）；④登录接口本身的实现细节（报错差异=枚举面，03 篇触发器表#9；JSON 还是 form；有没有堆栈泄露）；⑤**登录页引用的静态资源**（JS 里的接口字典、注释、测试账号——最常见的白给）。
- 止损线：五连测完无果且无注册口 → 挂起，季度复查（版本更新会开新面）。

**§3 弱口令测不出来**
- 症状：怀疑有弱口令但不能爆破（红线），怎么验证？
- 处置：合法路径三条——①**默认口令**（出厂/文档里的，一次尝试）：设备类（摄像头/防火墙/打印机）、中间件控制台（Druid/Nacos/Jenkins/XXL-JOB）、CMS 后台（安装文档默认值）；②**口令重置逻辑**代替口令猜测（重置链路弱=等效弱口令，且是可报告漏洞）；③**泄露库比对**（HaveIBeenPwned 类查目标域名邮箱的泄露记录——只确认「存在泄露」这一事实用于报告风险提示，不拿泄露凭据去登录，用泄露凭据登录超出授权范围）。
- 止损线：永远不爆破。这条没有止损线，是禁令。

**§4 验证码挡住关键流程**
- 症状：登录/注册/找回密码都有验证码，逻辑测试没法自动化。
- 处置：先测**验证码本身**（它经常就是最弱的环节）——①回显：响应包里有没有直接带出验证码/答案；②复用：同一验证码能否重复使用（删包重放）；③删除：去掉验证码参数还过不过；④固定：验证码是否长期不变；⑤打码：**手动打**（低频测试人手足够，不需要打码平台——打码平台+自动化=爆破节奏，触红线）。验证码全过不了且本身无洞 → 该流程关闭，打别的流程。
- 学习建议：「验证码五连测」做成 checklist 进你的目标卡模板——逻辑洞测试的第一步永远是先测守门的。

**§5 短信/邮件轰炸面**
- 症状：发现发送接口，想测轰炸。
- 处置：**注意边界**——「发送接口无频率限制」是可报告的逻辑缺陷（验证方式：**自己给自己**发 3-5 次确认无限制即停，写报告）；「对任意手机号批量发送」的验证**到「号码可控性证明」为止**（换一个你自己控制的第二个号码验证一次），**绝不对真实第三方号码发送**（骚扰+浪费目标短信费=破坏业务，触红线）。报告里用「可被滥用为短信轰炸，影响用户与厂商费用」描述危害，不需要真的轰出来。

**§6 注册功能关闭**
- 症状：需要账号的系统不开放注册。
- 处置：①找**旁路注册口**：APP 端注册常独立于 Web（02 §11）；小程序授权登录（微信一键登录常没关）；②找**测试账号**：JS/文档/泄露代码里的 test/demo 账号（02 §14）；③**无账号可测的面**先测完：未授权接口（不带 token 直接调业务接口——鉴权缺失的经典探测）、公开数据接口、静态资源越权（上传目录遍历）；④都不行 → 委托方申请测试账号（正规项目直接要，SRC 场景则此目标降级）。

**§7 默认口令清单失效**
- 症状：清单上的默认口令都被改了。
- 病因：默认口令是「安装后第一天」的洞，这个系统活了很久。
- 处置：思路从「猜口令」升级为「**找没改口令的兄弟**」——同一厂商产品在你雷达表里的其他部署实例（04 篇泛化逻辑：这家改了，那家未必）；以及**默认口令的变体**（产品文档里的初始口令+常见改法 `admin123/Admin@123/产品名@年份`——每个变体一次尝试，总量控制在 5 次内，超了就是爆破）。
- 止损线：5 次尝试原则。

**§8 老系统 N-day 找不到版本号**
- 症状：确认是某 CMS，但版本号藏了，CVE 对不上。
- 处置：版本推断四路——①**特征文件哈希**：静态资源（logo/js/css）内容哈希比对已知版本的发布包（本地下载官方各版本包比对——零请求成本）；②**功能特征**：某版本才有的接口/页面存在性探测（changelog 反推特征点，每版本 1-2 个请求）；③**报错指纹**：故意触发框架级报错看堆栈里的路径/类名版本痕迹；④**直接打「版本无关」的洞**：该 CMS 历史上从未修过的问题（配置类/设计类），不依赖版本号。
- 学习建议：给你的主粮生态（若依/JeecgBoot 系）建「版本特征表」（版本×特征文件哈希×特征接口），一次建表终身复用——这是补丁 diff 流水线（dojo 04 篇）的侦察侧配套。

**§9 PoC 打不通**
- 症状：版本对上了，公开 PoC 打了没反应。
- 处置：按序排查（这就是 03 篇假设驱动）——①**前提条件**：PoC 需要的配置/模块/接口在这台目标上存在吗（很多 PoC 默认开了某插件）；②**路径差异**：目标有 context-path/反代前缀，PoC 的路径要跟着变；③**版本微差**：同 CVE 在不同小版本 payload 细节不同（去看该 CVE 的**补丁 commit**——diff 会告诉你确切触发点，dojo 04 篇补丁考古）；④**防护介入**：是不是被 WAF 无声拦了（对照 06 篇 §定位拦截层）。全部排完还不通 → 该洞在此目标不成立，记录「已验证不可利用」防止未来重复劳动。
- 止损线：单 PoC 排查超过 2 小时 → 挂起，先打其他面。

**§10 打通了但没有回显**
- 症状：payload 发出去，页面无变化，不知道成没成。
- 处置：这是**神谕缺失**问题，不是漏洞问题——全套方案见 dojo 03 篇 §三（造神谕：时延/布尔/OOB/二次信道）和 06 篇 §五（信道战争）。SRC 场景特别注意：OOB 回连要用**可解释的域名**（你自己的 dnslog，报告里说明用途），且回连本身即证据，截图留档。

**§11 拿到执行能力但权限极低**
- 症状：命令能跑，`whoami` 是 nobody/最低权用户。
- 处置：**SRC 场景到此为止**——「已获得代码执行能力」+ whoami 输出 + 一个无害标识（如读取 web 配置文件证明文件系统可达）= 完整的 RCE 证据链，高危报告成立。**不要**继续提权/横向（那是 HW 项目的动作，需要单独的授权条款；SRC 授权不覆盖「拿下服务器之后的世界」）。报告里写「可执行系统命令，未进行任何后续操作」——这句话是你的合规护身符。
- HW/红队场景（有授权）：提权走 grimoire `提权` 分类 528 篇 + GTFOBins（库内 459 条），先在本地靶场核对内核/服务版本再上真机。

**§12 出网被封**
- 症状：能执行命令但目标不出网（OOB 收不到，反弹连不上）。
- 处置：无出网 RCE 的验证方式——①**文件证据**：读配置文件/写标识文件到 web 目录再 HTTP 访问（写文件到 web 目录属于「证明」级别的最小动作，报告后提示厂商清理）；②**时延/布尔**在命令执行层面的应用（`sleep`/条件真假）；③**内网侧证据**：`ip a`/`ps` 输出证明所处网络位置（只读命令）。报告评级话术：「无出网限制了即时危害，但目标位于内网 X 网段、可访问 Y 服务，具备横向基础」——影响链讲清楚，评级不掉。

**§13 容器里出不去**
- 症状：RCE 了但发现在 Docker 里。
- 处置：容器内证据三件套（都是只读）：`mount`/`.dockerenv` 证明容器环境、环境变量（**常含数据库凭据/云 AK——看到即停，报告里说明存在，不验证有效性或使用**）、挂载卷（宿主目录挂载=逃逸面，报告为风险项）。逃逸实操（privileged/挂载 socket 类）属 HW 授权动作，SRC 报告写到「存在逃逸风险配置」即可。云元数据 `169.254.169.254` 探测一次：可达+IMDSv1 = 直接高危证据（同样：取到「存在」即停，不翻凭证内容）。

**§14 内存马该不该用**
- 症状：想种内存马维持访问方便复测。
- 处置：**SRC 场景：不用，没有例外**——内存马=修改运行状态+持久化，双触红线（不破坏业务/不留后门），且检测困难=给厂商留隐患，被发现即职业生涯污点。你的 27 天计划早就写死了：内存马只在本地靶场验证技术。**HW 场景**：按你签的协议条款执行（协议明确允许才用，用完按协议清除并记录）。
- 学习建议：想学内存马技术本身 → 本地靶场+grimoire `内存马` 检索，技术与使用授权分开管理。

**§15 WAF 拦了 payload**
- 处置：全套见 dojo 06 篇（定位拦截层→四级对抗阶梯→差异/盲区两机制→信道战争）。SRC 场景补一条现实：**被 WAF 拦不等于洞不存在**——报告可以写「漏洞存在，当前被 WAF 规则缓解；WAF 为外挂防护，修复应以代码层为准」，附拦截证据。很多平台认这个（防护绕过另算一单的情况也有，看平台细则）。

**§16 日志里有我的痕迹**
- 症状：测试完意识到目标日志记录了全部动作。
- 处置：**这是正常且正确的状态**，不要试图删日志（删日志=反侦察=性质从测试变入侵，绝对红线）。你该做的：①测试动作本身保持「可解释」（最小探针纪律的意义就在这：日志被回看时，每个请求都是标准安全检查的样子）；②报告里主动列明测试时间窗和源 IP，方便厂商区分你和真实攻击者；③如果委托方要求隐蔽测试（HW），那是另一套授权协议的事。
- 一句话：让你的日志看起来像安全检查，而不是像攻击——这靠平时纪律，不靠事后清理。

**§17 入口点被修了**
- 症状：上周还在的洞，这周 404/403 了。
- 处置：①先确认是「修了」还是「临时下线/被 WAF 新规则盖了」（换最小探针重测，看响应特征）；②真修了：如果你没提交过——记入案例卡「时间窗」字段（该厂商修复速度和监测能力的情报，影响你未来对这个目标的节奏），然后**立即泛化**（dojo 04 篇：这个洞在同家族其他目标还在不在？修复往往滞后于家族）；③如果你提交过被修——正常流程，做修复复测（05 篇 §8）。
- 学习建议：「被抢先修复」不是损失，是免费情报：它告诉你这个厂商有主动监测，你的时间窗打法要调整为「发现→当天验证→当天提交」。

**§18 打进去发现是测试环境**
- 症状：拿下的系统数据是假的/配置是 dev 的。
- 处置：①**测试环境的洞照样报告**（多数平台收，评级可能降——报告里主动说明「判断为测试环境，依据：X/Y/Z」，诚实标注比被审核员发现强）；②测试环境的独特价值：**配置和代码常与生产同源**（报告里指出「测试环境暴露的生产配置/凭据」是独立的更高危发现——测试库里的生产数据库连接串是经典桥）；③从测试环境找生产的线索（内网段/域名规律/部署脚本），但**不横向过去**（生产是否在授权内？回 01 §10）。

## 【本篇学习建议】
1. 本篇 18 卡里，你的主战场是 §1-§10（入口证明层）；§11-14（后渗透层）在 SRC 场景全部「到证明为止」——**把「停在哪」背得比「怎么打」熟**，这是白帽和黑名单的分水岭。
2. §4 验证码五连测、§7 五次尝试原则、§8 版本特征表——三个可固化的 checklist/资产，本周建好。
3. 每张卡的「止损线」是给你冲刺期用的：27 天计划里时间盒纪律 > 单点执念，卡住按线撤退不纠结。
